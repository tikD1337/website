## Срез 8 целиком

Контент — месяцы работы: у ориентира 72 сценария и 10 курсов. Делим на
подсрезы, каждый играбелен сам по себе:

| Подсрез | Что | Почему в этом месте |
|---|---|---|
| **8Б** | Сеть: три сценария на готовом движке и его малых доработках | Дорожная карта: сеть первой — движок готов |
| 8В | Экземпляры: машины, люди и адреса меняются от экземпляра к экземпляру | Правило вариативности; обобщается на всю библиотеку разом |
| 8Г | Личность: истёкший пароль, кэш учётных данных и т. п. | Каталог готов со среза 3 |
| 8Д | Рабочий стол Windows: диск, профиль, обновления | Нужны новые механики машины |
| далее | Принтеры, ПО, мобильные, безопасность, инфраструктура; курсы и треки | По готовности инструментов |

## Зачем 8Б

Сеть — самая обжитая часть движка, и три новых сценария закрывают три
типичных обращения первой линии, которых в библиотеке нет: «по имени не
открывается», «интернета нет, а соседи работают», «розетка мёртвая».
У каждого — развилка, на которой очевидный шаг не срабатывает (правило
качества из дорожной карты).

Критерий успеха: три сценария проходятся образцово и ломаются на своих
ловушках (e2e по разделу на сценарий); вывод новых команд — эталонным
текстом; поломки приходят с сервера, как у остальных; визуальная
проверка проходит.

## Решения, принятые без пользователя

Пользователь: «делай что посчитаешь нужным, не нужно каждый раз спрашивать»;
на продолжение — «продолжай».

| Вопрос | Решение | Почему |
|---|---|---|
| Какие три сценария | DNS на списанном сервере; статический адрес с чужим шлюзом; порт в err-disabled из-за чужого устройства | У каждого развилка на готовом движке; «VPN» и «медленный линк» требуют новых механик |
| Вариативность | Не в 8Б: новые сценарии держат машину и человека константами в начале файла | 8В обобщит всю библиотеку разом; константы переводятся в параметры механически |
| Курсы и треки | Не в 8Б | Контент курсов — свой подсрез; иначе пакет разрастается |
| Источник DNS | Новое поле адаптера `dnsSource: 'dhcp' \| 'static'` | В Windows адрес бывает по DHCP, а DNS — вручную; `ipconfig /all` этого не показывает, `netsh` — показывает: это и есть диагностика |
| Порт-безопасность | Поля порта `errDisabled: 'psecure-violation' \| null` и `intruder: string \| null` (MAC чужого устройства) | Достаточно для сценария; полная модель port-security не нужна |
| Поднять порт | `shutdown` + `no shutdown` на своём порту; при подключённом чужом устройстве порт снова уходит в err-disabled | Так ведёт себя настоящий коммутатор; это и есть развилка |
| Править защиту порта | `switchport port-security …` — отказ шлюза (`deny`): первая линия защиту не ослабляет | Граница обозначается, а не прячется |

## Сценарии

Машины и люди — новые записи стартового мира, чтобы сценарии не делили
машину с имеющимися и в окне смены встречались вместе.

### 1. DNS на списанном сервере (`net-dns-stale-static`)

- **Поломка.** Адрес по DHCP, а DNS вручную: `10.20.14.9` — контроллер,
  выведенный из работы (`reachable: false`). Остался от настройки в
  старом офисе.
- **Симптом заявителя.** Сайты и портал «не открываются, пишет что-то
  про DNS»; почта в браузере тоже; при этом «вчера переставляли ноутбук».
- **Развилка.** `ipconfig /flushdns` — «Successfully flushed», ничего не
  меняется; `release` + `renew` — новая аренда, но DNS остаётся ручным.
  `nslookup` — «Request to 10.20.14.9 timed-out»; `ping 8.8.8.8` — отвечает.
  `netsh interface ip show dns` — «Statically Configured DNS Servers».
- **Решение.** `netsh interface ip set dns "Ethernet" dhcp` — DNS из
  области (`10.20.14.10`, `10.20.14.11`), проверка `nslookup`, звонок.
- **Ловушка (тихая поломка).** Прописать вручную `8.8.8.8`: интернет
  заработает, внутренние имена (`internal-portal.arcline.corp`) — нет.

### 2. Статический адрес с чужим шлюзом (`net-static-wrong-gateway`)

- **Поломка.** DHCP выключен: `10.20.14.97/24`, шлюз `10.20.14.254`
  (несуществующий), DNS `10.20.14.10`. Остался после стенда.
- **Симптом.** Нет интернета и портала; общая папка на соседнем
  компьютере открывается; «у коллег всё работает».
- **Развилка.** `ipconfig /renew` — «The operation failed as no adapter
  is in the state permissible for this operation.» (адаптер без DHCP).
  `ping 8.8.8.8` — «Reply from 10.20.14.97: Destination host
  unreachable.»; `ping 10.20.14.1` (настоящий шлюз сегмента) — отвечает.
  `netsh interface ip show config` — «DHCP enabled: No».
- **Решение.** `netsh interface ip set address "Ethernet" dhcp` → аренда
  из области VLAN, шлюз и DNS из DHCP; проверка `ping`, звонок.
- **Ловушка (тихая поломка).** Исправить только шлюз статически
  (`… static 10.20.14.97 255.255.255.0 10.20.14.1`): работает, но адрес
  из пула DHCP закреплён вручную — конфликт при следующей выдаче.

### 3. Порт отключён защитой (`net-port-security`)

- **Поломка.** Заявитель подключил к розетке стола личный мини-коммутатор
  (второй ноутбук); порт с port-security (один MAC) ушёл в err-disabled.
  Мини-коммутатор так и подключён (`intruder`).
- **Симптом.** «Нет сети совсем, значок с крестиком»; кабель «вставлен».
- **Развилка.** `ipconfig` — «Media disconnected»; переподключение
  адаптера не помогает. В консоли коммутатора: `show interfaces status`
  — `err-disabled`; `show logging` — `%PM-4-ERR_DISABLE: psecure-violation
  error detected on Gi1/0/…` и `%PORT_SECURITY-2-PSECURE_VIOLATION … MAC
  address …`. `shutdown` + `no shutdown`, пока чужое устройство в
  розетке, — порт снова err-disabled (новая запись в журнале).
- **Решение.** Попросить заявителя убрать мини-коммутатор (просьба
  открывается прочтением журнала коммутатора), затем `shutdown` +
  `no shutdown` на своём порту, проверка `ipconfig`, звонок.
- **Ловушки.** Поднять порт, не убрав причину (порт падает снова — не
  тихая, а видимая неудача); `switchport port-security …` — отказ шлюза,
  записанный опасным действием.

## Движок

**Адаптер.** `dnsSource: 'dhcp' | 'static'` (в стартовом мире у всех
`'dhcp'`). `acquireLease` не трогает DNS при `'static'`. `ipconfig
/renew` и `/release` на адаптере с `dhcpEnabled: false` — заголовок и
«The operation failed as no adapter is in the state permissible for this
operation.», код выхода 1.

**`netsh interface ip`** (и синоним `ipv4`), имя интерфейса — `"Ethernet"`
или `name="Ethernet"`:

| Команда | Действие и вывод |
|---|---|
| `show config` | блок «Configuration for interface "Ethernet"» — DHCP enabled, IP Address, Subnet Prefix, Default Gateway, Gateway Metric, InterfaceMetric, DNS (через DHCP или статически), Register with which suffix, WINS |
| `show dns` | тот же заголовок, DNS и суффикс |
| `set dns <имя> dhcp` / `source=dhcp` | `dnsSource: 'dhcp'`, DNS из области сегмента; вывод пустой |
| `set dns <имя> static <ip>` | `dnsSource: 'static'`, `dns: [ip]`; вывод пустой |
| `set address <имя> dhcp` | `dhcpEnabled: true`, аренда как у `renew`; вывод пустой |
| `set address <имя> static <ip> <маска> [<шлюз>]` | `dhcpEnabled: false`, адрес, маска, шлюз; вывод пустой |
| неизвестное имя | «The filename, directory name, or volume label syntax is incorrect.», код 1 |

Значения выравниваются с 43-й позиции, продолжение списка DNS — с той же.
Каждое изменение — запись в журнал изменений сессии, как у остальных
операций над машиной; окно и команда — одна операция (`core/device`).

**`ping`.** Шлюз адаптера не совпадает со шлюзом сегмента — внешние адреса
отвечают «Reply from <свой адрес>: Destination host unreachable.» четыре
раза, статистика «Received = 4, Lost = 0 (0% loss)» без строки времён —
так считает Windows. Адреса своей подсети отвечают как прежде.

**Порт коммутатора.** `errDisabled` и `intruder`; статус порта
`err-disabled` в `show interfaces status` и `show interfaces <if>` («is
down, line protocol is down (err-disabled)»); линк машины падает. `no
shutdown` при `intruder` — снова err-disabled с двумя записями журнала;
без `intruder` — порт поднимается. Просьба «уберите мини-коммутатор»
убирает `intruder`. Флаг сессии `switchLogRead` — по `show logging` на
коммутаторе тикета; он открывает просьбу.

**Шлюз полномочий.** `switchport port-security` в любой форме — `deny`
«первая линия не меняет защиту порта», опасное действие в журнал.

## Тесты

- e2e — по разделу на сценарий: образцовый проход (full) и каждая
  ловушка (тихая поломка или неудача, видная в разборе);
- вывод `netsh interface ip show config` / `show dns`, `ipconfig /renew`
  на статическом адаптере, `ping` с чужим шлюзом, `show interfaces
  status` с err-disabled, `show logging` — эталонным текстом целиком;
- «окно и команда неотличимы» — если для DNS и адреса появится окно
  (в 8Б окна нет: только команда);
- утечка разгадки в модель и в бандл — общие тесты по всей библиотеке
  подхватывают новые сценарии сами.

## Не делаем

- Окно «Свойства адаптера» — только `netsh`.
- VPN, медленный линк, дубль адреса — новые механики, позже.
- Вариативность — подсрез 8В.
