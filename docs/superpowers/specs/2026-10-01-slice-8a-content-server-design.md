# Срез 8А — сервер контента

> Спека подсреза. Общая спека: `2026-09-09-helpdesk-simulator-design.md`.
> Идёт перед контентом (срез 8): новый контент сразу живёт на сервере.
> Предыдущий срез — 7Б, интервью (`2026-09-30-slice-7b-interview-design.md`).

## Зачем

Пользователь: «сделай чтобы нельзя было ничего украсть с сайта, потому что
например можно зайти на /assets/index-….js и все украсть». Сегодня бандл
несёт весь контент открытым текстом: корневые причины, цели, условия
починки, тексты просьб, верные ответы курсов, пункты и образцовые ответы
интервью. Одного `curl` хватает, чтобы унести всё.

Файл, который браузер запускает, браузер обязан скачать, — запретить это
нельзя. Можно убрать из него ценное: контент и оценка уезжают на сервер,
браузер получает только то, что нужно для хода игры, и только тогда,
когда этот ход наступил.

Критерий успеха: в публичном бандле нет ни одного файла из `src/scenarios`,
`src/courses`, `src/interviews` и ни одной строки решения (проверяется
тестом по всей библиотеке); разбор с корневой причиной приходит только
после закрытия тикета; верные ответы курса — только после ответа; пункты
интервью — только в разборе; все сценарии, курс и интервью проходятся
целиком через сервер; сервер работает на Raspberry Pi 3 за nginx и
Cloudflare.

## Что сказал пользователь

- Выбрал «контент на сервере» из трёх вариантов (сервер / помеха для
  `curl` / оставить как есть).
- «не обязательно чтобы тренажер оставался полностью оффлайн, я этого
  вроде как никогда не говорил» — жёсткое требование «оффлайн» снято.
  «Бесплатно» остаётся: сервер — своя машина пользователя.
- «у меня лежит сайт на raspberry pi 3» — сервер там же, где сайт.
- Репозиторий на GitHub пользователь сделает приватным сам.

## Решения, принятые без пользователя

Пользователь: «делай что посчитаешь нужным, не нужно каждый раз спрашивать».

| Вопрос | Решение | Почему |
|---|---|---|
| Где идёт симуляция | В браузере, как сейчас: мир, терминал, окна, каталог | Перенос мира на сервер — переписать всё; Pi 3 и сеть добавили бы задержку каждой команде |
| Что уходит на сервер | Всё, что решает: условия починки, просьбы, оценка, причина, цели; ответы курсов; пункты и ход интервью | Это и есть «украсть» — разгадка, а не код окон |
| Что браузер получает заранее | Каталог: карточки тикетов, оглавления курсов, названия треков | Это видно в очереди и в списке курсов и так |
| Когда приходит поломка | Капсула тикета — при входе тикета в окно смены, как сейчас приходит поломка | Правило «поломка входит в мир вместе с тикетом» остаётся; мир сломан в браузере, значит патч поломки браузер видит — это честная граница |
| Без своего состояния | Сервер не хранит ни смен, ни прогресса: клиент присылает мир, журнал, запуск интервью | Нет учёток, нет базы, Pi перезапускается без потерь; подделка своего мира обманывает только самого игрока |
| Привязка к тикету | Капсула несёт подпись (HMAC сценария и времени выдачи, 24 ч); проверка, просьбы и оценка без подписи — отказ | Иначе разбор любого сценария вынимался бы одним запросом с пустым журналом |
| Против выкачивания | Лимиты на IP: капсулы, уроки, старт интервью | Всё, что видит игрок, можно сохранить, — лимит превращает «одним циклом за секунду» в часы |
| Синхронный стор в тестах | Разъём `ContentPort` с ответом «значение или промис»; локальная реализация отвечает сразу, сетевая — промисом | 346 тестов идут на локальном разъёме без `await`; асинхронный путь проверяется своими тестами |
| Один код оценки | Сервис контента — те же функции ядра; локальный разъём зовёт его напрямую, HTTP — через обработчик | Оценка в тестах и на сервере не может разойтись |
| Обработчик | Стандартный `(Request) => Promise<Response>` | Один обработчик для Node на Pi, для dev-сервера Vite и для теста эквивалентности |
| Зависимости сервера | Ноль: `node:http`, `node:crypto`; один файл сборки esbuild | Pi 3, Node ≥ 18 из пакетов Raspberry Pi OS |
| Ошибки сети | Плашка со словами и «Повторить»; тикет при сбое оценки остаётся открытым | Молча потерянная оценка хуже повторного нажатия |
| Старые записи истории | Разбор без причины, если её нет в записи | Причина теперь хранится в карточке; отдать её по запросу значило бы открыть дыру |
| Worker `website` и Pages | Пользователь удаляет: они раздают старые полные бандлы | Иначе защита обходится старым адресом |

## Модель угроз

Защищено:
- `curl` бандла не даёт ничего из контента;
- разбор, причина и цели — только оценкой закрытого тикета с подписью;
- условия починки и тексты просьб — только ответом сервера на конкретный
  мир взятого тикета;
- верный ответ курса — только после ответа, верные ответы квиза — только
  после сдачи (правило «несданный квиз не выдаёт ответов» теперь держит
  сервер);
- пункты, маркеры и образцовые ответы интервью — только в разборе;
- массовое выкачивание упирается в лимиты.

Не защищено, и это сказано прямо:
- что игрок видит, играя, — сохраняется: поломку в капсуле, разбор после
  закрытия, текст урока;
- скрипт, играющий за человека, со временем соберёт всё;
- код движка остаётся в бандле — без контента тренажёра из него не
  собрать.

## Разъём контента — `src/content/`

```ts
type MaybePromise<T> = T | Promise<T>

/** Карточка сценария: то, что видно в очереди. */
interface ScenarioMeta {
  id: string; category: string; subcategory: string
  priority: 'P1' | 'P2' | 'P3' | 'P4'; service: string
  summary: string; description: string; requester: string; device: string
  slaResponseHours: number; slaResolveHours: number
  resources?: string[]
}

/** Капсула тикета: что нужно браузеру, чтобы тикет игрался. */
interface Capsule {
  scenarioId: string
  token: string                       // подпись сервера
  inject: InjectPatch[]               // поломка
  persona: Persona                    // knows, doesntKnow, canDoIfAsked, scripted
  confirmReplies: [string, string]
  asks: Array<{ id: string; unlockedBy?: string }>  // без текстов
}

interface Catalog { scenarios: ScenarioMeta[]; courses: CourseOutline[]; tracks: TrackMeta[] }

interface AskResult { ask: string; reply: string; effect: InjectPatch[]; relogin?: string }
interface GradeResult { scorecard: Scorecard; onEscalate: InjectPatch[] }  // scorecard.rootCause

interface ContentPort {
  catalog(): MaybePromise<Catalog>
  capsule(scenarioId: string): MaybePromise<Capsule>
  problemGone(c: Capsule, world: WorldState): MaybePromise<boolean>
  askTexts(c: Capsule, flags: Record<string, unknown>): MaybePromise<Record<string, string>>
  ask(c: Capsule, askId: string, world: WorldState, flags: Record<string, unknown>): MaybePromise<AskResult | null>
  grade(c: Capsule, input: { world: WorldState; ticket: Ticket; session: Session }): MaybePromise<GradeResult>
  lesson(course: string, section: string, lesson: string): MaybePromise<LessonContent>
  check(course: string, section: string, lesson: string, check: string, answer: Answer): MaybePromise<CheckVerdict>
  quiz(course: string, section: string): MaybePromise<QuizContent>
  submitQuiz(course: string, section: string, answers: Answer[]): MaybePromise<QuizGrade>
  interviewStart(track: string, attempt: number, solved: Solved[]): MaybePromise<InterviewRun>
  interviewAnswer(run: InterviewRun, text: string): MaybePromise<{ run: InterviewRun; next: string | null }>
  interviewFaq(track: string, text: string): MaybePromise<string | null>
  interviewGrade(run: InterviewRun): MaybePromise<InterviewResult>
}
```

Сбой сетевого разъёма — `ContentError` с видом `unavailable` (нет связи,
5xx), `expired` (подпись не принята), `limited` (429), `bad` (400) и
русским текстом для плашки.

Три реализации одного контракта:
- **сервис** (`src/content/server/service.ts`) — получает библиотеки и
  секрет, проверяет их загрузчиками при создании (`validateScenarios`,
  `validateCourses`, `validateInterviews` переезжают сюда из стора) и
  считает всё функциями ядра;
- **локальный разъём** — сервис без сети, синхронно; им пользуются тесты;
- **сетевой разъём** (`src/content/remote.ts`) — `fetch` к `/api`.

Клиент импортирует только `src/content/port.ts` (типы, `ContentError`,
помощник `then(value, fn)` для «значение или промис») и `remote.ts`.
Сервис, библиотеки и `node:crypto` — только сервер, dev-сервер и тесты.

## Сценарии

**Каталог** — `ScenarioMeta` всех сценариев. Генератор очереди работает
на нём: занятость машины (`device`) и общих ресурсов, карточка тикета
(`buildTicket` принимает `ScenarioMeta`).

**Пополнение очереди** делится на два шага с одним правилом выбора:
`planFill(g, metas)` — какие сценарии войдут в окно (не меняет `g`);
`fillQueue(g, metas, world, injectFor)` — вносит их и ломает мир патчем
из капсулы. Стор между шагами получает капсулы. Сбой — очередь остаётся
прежней, пул не тронут, плашка «Сервер недоступен» с «Повторить».

**Подпись**: `base64url(HMAC-SHA256(секрет, "<сценарий>.<время выдачи>"))`
плюс время выдачи; срок 24 часа. Секрет — `SYSADMIN_SECRET` или файл
`<DATA_DIR>/secret` (создаётся при первом запуске, права 0600); в
dev-сервере — случайный на процесс.

**Где решение спрашивается у сервера**:

| Место | Было | Стало |
|---|---|---|
| «Проверьте, всё ли работает» (`confirmWithUser`) | `allHold(world, fixedWhen)` | `problemGone(капсула, мир)`; реплики — из капсулы |
| Сводка модели (`say`) | `briefFor(scenario, …)` | персона из капсулы + `problemGone` |
| «Попробуйте сейчас» после ответа (`say`) | `allHold(after.world, fixedWhen)` | `problemGone` по миру после ответа |
| Кнопки просьб (`TicketView`) | `scenario.asks` из состояния | `askTexts(капсула, флаги)` — тексты открытых просьб |
| Просьба (`askRequesterTo`) | эффект и ответ из сценария | `ask(…)`: сервер применяет эффект к копии мира, отвечает репликой; браузер применяет эффект и повторный вход к своему миру |
| Закрытие (`resolveTicket`) | `gradeIncident` в браузере | `grade(…)` на копии тикета в статусе «решён»; запись, очередь и мир правятся только после ответа |

Правила, которые остаются в сторе: просьба без открывающего флага —
отказ до сети; закрытие без кода — отказ до сети. Сервер проверяет
флаги просьбы ещё раз.

**Асинхронность.** Каждое место, где ответ сервера приходит промисом,
проверяет устаревание тем же способом, что `say`: тикет тот же объект,
всё ещё назначен, смена та же. Пока идёт оценка, `grading: true`, кнопка
закрытия неактивна, повторное закрытие — отказ. Сбой оценки: тикет
открыт, плашка с текстом ошибки.

**Карточка разбора** получает `rootCause`; `ScorecardView` берёт причину
из карточки, а не из библиотеки. Запись прошлого формата без причины
читается целиком, разбор показывает её без раздела причины.

## Курсы

- `CourseOutline` — курс без содержания: id и названия секций и уроков,
  id проверок урока, `practice`, число вопросов квиза. На нём считаются
  статусы (`courseState`) — клиенту больше ничего не нужно.
- `lesson(...)` → `LessonContent`: блоки урока и проверки без `correct`,
  `why`, верных ответов и разборов ввода. Урок грузится при открытии и
  хранится в памяти стора до перезагрузки.
- `check(...)` → вердикт и разбор выбранного (тот же `AnswerResult`).
- `quiz(...)` → вопросы без ответов; `submitQuiz(...)` → `QuizGrade`:
  разбор выбранного всегда, верные ответы — только при сдаче.
- Стор не пускает в закрытый урок и квиз, как сейчас; сервер прогресса
  не знает и отдаёт урок по адресу — это закрывает лимит.

## Интервью

- `TrackMeta` — id, название, описание, интервьюер, факты о компании.
- Запуск интервью (`InterviewRun`) — данные с id вопросов и сказанными
  репликами, без пунктов; его носит клиент. Сервер проверяет присланный
  запуск как `unknown`: трек, план, индекс.
- `interviewStart` и `interviewAnswer` — функции `core/interview/flow` на
  сервере: уточнение и следующий вопрос решает сервер, потому что для
  этого нужны маркеры.
- `interviewFaq` — заготовки ответов на вопросы кандидата.
- `interviewGrade` → `InterviewResult`, у каждого вопроса — пункты с
  названием и разбором (`points: {id, label, why}[]`): разбор больше не
  читает трек. Запись прошлого формата показывает пункты своими id.

## HTTP — `src/content/server/http.ts`

| Метод и путь | Тело | Ответ |
|---|---|---|
| `GET /api/catalog` | — | `Catalog` |
| `POST /api/scenario/capsule` | `{ id }` | `Capsule` |
| `POST /api/scenario/state` | `{ token, world }` | `{ problemGone }` |
| `POST /api/scenario/asks` | `{ token, flags }` | `{ texts }` |
| `POST /api/scenario/ask` | `{ token, askId, world, flags }` | `AskResult \| null` |
| `POST /api/scenario/grade` | `{ token, world, ticket, session }` | `GradeResult` |
| `POST /api/course/lesson` | `{ course, section, lesson }` | `LessonContent` |
| `POST /api/course/check` | `{ course, section, lesson, check, answer }` | `CheckVerdict` |
| `POST /api/course/quiz` | `{ course, section }` | `QuizContent` |
| `POST /api/course/quiz/submit` | `{ course, section, answers }` | `QuizGrade` |
| `POST /api/interview/start` | `{ track, attempt, solved }` | `InterviewRun` |
| `POST /api/interview/answer` | `{ run, text }` | `{ run, next }` |
| `POST /api/interview/faq` | `{ track, text }` | `{ reply }` |
| `POST /api/interview/grade` | `{ run }` | `InterviewResult` |

Ошибки — JSON `{ error: "<русский текст>" }`: 400 неверный запрос
(любое исключение сервиса на чужих данных — 400, а не падение процесса),
403 подпись, 404 путь, 413 тело больше 1 МБ, 429 лимит с `Retry-After`.

**Лимиты** — корзина на IP (`CF-Connecting-IP`, затем `X-Real-IP`, затем
адрес сокета), время — инжектируемые часы:

| Что | Запас | Пополнение |
|---|---|---|
| капсула | 30 | 1 в 20 секунд |
| урок и квиз | 40 | 1 в 15 секунд |
| старт интервью | 6 | 1 в 2 минуты |
| любой запрос | 120 | 2 в секунду |

Первые значения (12 / 1 в минуту, 20 / 2 в минуту, 3 / 1 в 5 минут)
запирали тренажёр после четырёх перезагрузок подряд — найдено в
браузере при проверке среза: лимит против скрипта, а не против F5.

## Сборка и выкладка

- `npm run build` — клиент в `dist/`, без контента.
- `npm run build:server` — `server-dist/sysadmin-fun.mjs`: esbuild, Node
  18, один файл, без зависимостей.
- `npm run dev` — Vite с тем же обработчиком на `/api` (плагин как у
  прокси модели).
- `deploy/` — unit systemd (`127.0.0.1:8787`, `DynamicUser`,
  `StateDirectory`), фрагмент nginx (`/api/` → сервер, заголовки запрета
  встраивания, `/_headers` → 404) и порядок выкладки:
  1. собрать оба, скопировать на Pi, перезапустить службу;
  2. **удалить старые файлы из `assets/` на Pi** — там полные бандлы;
  3. очистить кэш Cloudflare;
  4. удалить проект Pages `sysadmin-fun` и Worker `website` в Cloudflare
     (оба раздают старые полные бандлы); после удаления Worker убрать
     `wrangler.jsonc`, иначе пуш снова будет падать;
  5. сделать репозиторий приватным.

## Тесты

По правилам CLAUDE.md «Какие тесты писать». Новые обязательные:
- **утечка в бандл**: esbuild собирает `src/main.tsx` с метафайлом — ни
  одного входа из `src/scenarios`, `src/courses`, `src/interviews`,
  `src/content/server`; ни одной корневой причины, разбора варианта,
  образцового ответа из библиотеки в тексте сборки;
- **утечка в ответы до срока** — по всей библиотеке: капсула, оглавление,
  урок, квиз, запуск интервью и ответ на ход не содержат причины, целей,
  условий починки, текстов просьб, тихих поломок, «чего избегать»,
  верных ответов и разборов, пунктов и образцовых ответов;
- **сеть и локальный разъём неотличимы**: образцовый проход сценария
  через HTTP-обработчик даёт ту же карточку, что через локальный;
- **подпись**: чужая, подделанная, просроченная — отказ;
- **лимиты**: корзина исчерпывается, 429, пополняется по часам;
- **устаревание**: ответ оценки после сброса смены отбрасывается;
  повторное закрытие во время оценки — отказ; сбой оценки оставляет тикет
  открытым;
- **кривые тела** — 400, процесс жив.

Существующие тесты идут на локальном разъёме; меняется только то, как они
создают стор.

## Не делаем

- Учёток, прогресса на сервере, синхронизации между устройствами.
- Обфускацию, привязку к домену, блокировку инструментов разработчика —
  см. CLAUDE.md «Что от копирования защищает на самом деле».
- Прокси модели на сервере — отдельная задача («свой эндпоинт»).
- Перенос симуляции мира на сервер.
