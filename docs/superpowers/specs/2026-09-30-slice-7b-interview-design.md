# Срез 7Б — комната интервью

> Спека подсреза. Общая спека: `2026-09-09-helpdesk-simulator-design.md`,
> раздел 9 («Курсы и интервью»). Дорожная карта: задачи 7.4–7.5.
> Предыдущий подсрез — 7А, курсы (`2026-09-30-slice-7a-courses-design.md`).

## Зачем

Тикеты учат делать, курсы — понимать, интервью — объяснять. На
собеседовании в поддержку спрашивают ровно то, что тренажёр уже
отрабатывает: что значит 169.254, чем блокировка отличается от
забытого пароля, когда эскалировать. Здесь это можно проговорить
вслух и получить разбор: что вы показали, чего не хватило, какого
ответа ждали.

Критерий успеха: интервью проходится целиком — знакомство → вопросы →
ваш опыт → ваши вопросы → вердикт — и без модели, и с ней; разбор
называет по каждому вопросу прозвучавшие и пропущенные пункты и
образцовый ответ; вопрос об опыте задаётся про тикет, который вы
действительно закрывали; попытки переживают перезагрузку.

## Решения, принятые без пользователя

Пользователь: «делай что посчитаешь нужным, не нужно каждый раз
спрашивать»; на 7Б — «да давай некст».

| Вопрос | Решение | Почему |
|---|---|---|
| Кто ведёт интервью | Детерминированный движок: порядок вопросов, уточнение, переход к этапу, вердикт. Модель — только реплика-реакция интервьюера и ответы на вопросы кандидата | Разбор должен быть воспроизводим и работать оффлайн; модель оживляет разговор, но не решает |
| Как оценивается ответ | Чек-лист пунктов у каждого вопроса; пункт прозвучал, если в ответе есть один из его маркеров (основа слова, команда) | «Без модели — разбор по чек-листу» — дорожная карта; оценка та же при любом режиме |
| Что знает модель | Этап, текст заданного вопроса, реплики разговора, факты о компании. Пунктов чек-листа и образцовых ответов — нет | Как с корневой причиной: знающий ответ интервьюер подсказывает его уточнением. Проверяется тестом по всей библиотеке |
| Реакция модели на ответ | Одна-две фразы без оценки и подсказок; следующий вопрос — текстом контента | Вопрос — единица разбора; если его формулирует модель, разбору не с чем сверяться |
| Уточнение | Один раз, если после первого ответа прозвучало меньше половины пунктов; пункты второго ответа засчитываются | Так спрашивает живой интервьюер: «а если это не помогло?» — второй шанс, но не бесконечный |
| Вопрос об опыте | Про сценарий из вашей истории, закрытый не провалом; если таких нет — общий вопрос о трудном случае | Спрашивать про то, что вы делали, честнее, чем про выдуманное; разбор знает, какой была причина |
| Выбор вопросов | Пул из 10 технических, в интервью — 5, по кругу от номера попытки | Детерминированно и без повторения подряд; случайности в ядре нет |
| Вердикт | «Рекомендован»: технические ≥ 70 %, опыт ≥ 50 %, задан хотя бы один вопрос. «Под вопросом»: технические ≥ 45 %. Иначе «Не рекомендован» | Интервьюер ценит вопросы кандидата: промолчать в конце — плохой знак и в жизни |
| Где живёт | Инструмент «Интервью» после «Курсов»; от очереди и мира не зависит | Собеседование — не смена: тикеты и мир оно не трогает |
| Незаконченное интервью | Не сохраняется: перезагрузка начинает заново | То же правило, что у незакрытого тикета |
| Очки | Нет | Оценка считает работу по тикету |
| Накачка ответа маркерами | Не ловится | Тренажёр для одного человека: список ключевых слов обманывает только его самого — как правка счёта из консоли |

## Модель — `core/interview/`

```ts
type Stage = 'intro' | 'technical' | 'experience' | 'questions' | 'done'

interface Point { id: string; label: string; markers: string[]; why: string }

interface Question {
  id: string
  stage: 'intro' | 'technical' | 'experience'
  prompt: string            // для опыта может содержать {тикет}
  points: Point[]
  expected: string          // образцовый ответ — только для разбора
  followUp?: string
  scenario?: string         // вопрос об опыте: по какому сценарию
}

interface InterviewTrack {
  id: string; title: string; summary: string
  interviewer: string       // имя и роль интервьюера
  company: string[]         // факты о компании — для модели и для ответов
  intro: Question
  technical: Question[]     // пул
  perInterview: number      // сколько технических в одном интервью
  experience: Question[]    // по сценариям и один общий (без scenario)
  faq: Array<{ ask: string; reply: string }>
}
```

- **Маркеры** сравниваются после нормализации: нижний регистр, `ё` → `е`,
  схлопнутые пробелы; маркер — подстрока («разблокир» ловит все формы).
- **Ход интервью** — `InterviewRun`: план (id вопросов по порядку),
  текущий вопрос, было ли уточнение, ответы по вопросам, стенограмма,
  вопросы кандидата. Операции чистые: `startInterview(track, attempt,
  solved)`, `answer(run, text)` → следующая реплика интервьюера и новый
  ход, `askInterviewer(run, text)`, `finishQuestions(run)`.
- **Оценка** — `gradeInterview(track, run): InterviewResult`: по каждому
  вопросу — ответы, прозвучавшие и пропущенные пункты, доля, образцовый
  ответ; доли по этапам; сколько вопросов задал кандидат; вердикт.
- **Загрузчик** `validateInterviews(tracks, scenarioIds)`: id уникальны,
  у вопроса есть пункты, у пункта — маркеры и разбор, у вопроса — образцовый
  ответ, `scenario` существует, общий вопрос опыта есть, пул технических
  не меньше `perInterview`.

## Разъём диалога

Вызов модели отделяется от сборки промпта: `askModel(messages, cfg,
fetch)`. Разъём получает второй метод — `interview(req)`: свой промпт
интервьюера (`interviewPrompt.ts`), те же настройки, размыкатель и
проверка ответа (`sanitize.ts`), та же деградация на заготовки с
плашкой. Запрос интервьюера: трек (имя, факты о компании), этап, текст
текущего вопроса, реплика кандидата, история. Заготовки без модели:
нейтральная реакция по кругу («Понятно.», «Хорошо, спасибо.»), ответы на
вопросы кандидата — из `faq` по тому же совпадению, что у заявителя
(`similarity`), иначе «Это лучше обсудить на следующем этапе».

## Прогресс

`Progress.interviews: InterviewRecord[]` — `{ id, track, at, attempt,
result: InterviewResult }`. Прошлый формат без поля — «интервью не
было»; битая запись — ошибка проверки. Гидратация дописывает загруженные
перед накопленными. «Стереть прогресс» стирает и интервью.

## Стор

- `interview: InterviewRun | null`, `interviewBusy: boolean`,
  `interviewNotice: string | null`, `interviewOpen: string | null` — какой
  разбор открыт.
- `startInterview(track)`; `answerInterview(text): Promise<void>` —
  реакция модели, затем следующий вопрос; `askInterviewer(text)`;
  `finishInterview()` — оценка, запись в прогресс, разбор открыт.
- Асинхронный ответ проверяется на устаревание: интервью начато заново
  или брошено, пока модель думала, — ответ отбрасывается.
- Интервью не трогает `session`, очередь и мир.

## Интерфейс

- **«Интервью»**: описание трека и этапов, «Начать интервью», история
  попыток (дата, вердикт, технические, опыт).
- **Комната**: этапы по порядку с текущим, лента реплик, поле ответа
  (`Ctrl+Enter` отправляет), микрофон и озвучка — как в «Связи», если
  включены; на этапе «Ваши вопросы» — «Спросить» и «Вопросов больше нет».
  Плашка, когда отвечают заготовки вместо модели.
- **Разбор**: вердикт, доли по этапам, по каждому вопросу — ваш ответ,
  пункты «прозвучало / нет» с объяснением пропущенных, образцовый ответ.
- **Профиль**: последний вердикт интервью.

## Трек «Первая линия: собеседование»

Интервьюер — руководитель первой линии Arcline. Знакомство: коротко о
себе и почему поддержка. Технические (пул 10): APIPA и порядок
`release`/`renew`; блокировка против забытого пароля; сверка личности;
доступ через группы и повторный вход; служба, остановленная после
падений; «у всего этажа нет сети»; Code 43 и замена; гарантия и RMA;
эскалация — когда и с чем; заметка о решении. Опыт — по одному вопросу
на сценарии библиотеки и общий о трудном случае. FAQ — смены, дежурства,
вторая линия, инструменты, обучение, рост.

## Тесты

- `interview`: оценка ответа — таблица литералов (маркер, форма слова,
  `ё`, пусто); ход — уточнение один раз и только при недоборе, опыт из
  истории, круг пула; вердикт — пороги; загрузчик — таблица испорченного.
- разъём: промпт интервьюера не содержит пунктов, маркеров, образцовых
  ответов и уточнений — по всей библиотеке треков; отказ модели —
  заготовка с плашкой.
- `validate`: прошлый формат без `interviews`; битая запись — ошибка.
- стор: устаревший ответ отбрасывается; законченное интервью записано.
- `e2e`: интервью без модели от знакомства до разбора, вердикт и пункты
  литералами.
