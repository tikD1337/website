# Срез 7А — курсы

> Спека подсреза. Общая спека: `2026-09-09-helpdesk-simulator-design.md`,
> разделы 7 («Курсы») и 9. Дорожная карта: задачи 7.1–7.3. После этого —
> 7Б, комната интервью (задачи 7.4–7.5).

## Зачем

Тикеты учат делать, курсы — понимать, почему так. В оригинале курс —
уроки с проверками внутри, секции открываются по квизам, а урок ведёт
на тренировочный тикет. Здесь то же: прочитал про APIPA, ответил на
проверки, нажал «Взять тикет» — и чинишь ту самую поломку в том же
мире, где работает очередь.

Критерий успеха: курс «Первая линия» (4 секции × 4 урока, квиз на
каждую секцию) проходится целиком; следующая секция открывается только
сданным квизом, следующий урок — пройденным предыдущим; неверный ответ
объясняется словами; урок открывает свой тикет, не нарушая правила
«один в работе»; всё переживает перезагрузку.

## Декомпозиция среза 7

Срез 7 — две независимые подсистемы, как срез 6 был тремя:

- **7А — курсы** (эта спека): движок уроков, проверки, квизы секций,
  связь с практикой, первый курс.
- **7Б — интервью**: комната (знакомство → вопросы → ваш опыт → ваши
  вопросы → вердикт) и разбор; разъём диалога с деградацией на готовые
  вопросы. Своя спека после 7А.

Общего у них — только память (`Progress`) и место в навигации.

## Решения, принятые без пользователя

Пользователь 27.09: «делай что посчитаешь нужным, не нужно каждый раз

| Вопрос | Решение | Почему |
|---|---|---|
| Где живёт курс | Модулем TypeScript в `src/courses/`, как сценарии; загрузчик проверяет его при запуске | Офлайн и детерминированно; опечатка автора падает сразу, а не у ученика на шестом уроке |
| Сколько контента | Один полный курс в масштабе оригинала: 4 секции × 4 урока, ~4 проверки в уроке, квиз из 5 вопросов на секцию | Движок доказывается на настоящих размерах; остальные курсы — срез 8 |
| Что открывается последовательно | Секции — по сданному квизу предыдущей; уроки внутри секции — по пройденному предыдущему; квиз — когда пройдены все уроки секции | «Секции открываются последовательно по квизам» — механика оригинала; уроки по порядку, потому что каждый опирается на прошлый |
| Когда урок пройден | Все его проверки отвечены верно | Урок без проверки проходился бы сам — загрузчик такой не пропускает, как цель без доказательств |
| Порог квиза | Не меньше 80 %: 4 из 5 | Одна ошибка простительна, две — повод перечитать |
| Что показывает несданный квиз | Почему выбранный ответ неверен — и только; верные ответы — после сдачи | Иначе пересдача превращается в переписывание ответов с экрана |
| Практика обязательна? | Нет: урок показывает, проходили ли вы этот сценарий и с каким вердиктом, но открытие не ждёт тикета | Очередь — окно смены; ставить курс в зависимость от того, что пришло в окно, значило бы запирать уроки случайностью |
| Практика и «один в работе» | Урок открывает тикет теми же правилами, что и очередь; при чужом тикете в работе — отказ словами очереди | Курс — не чёрный ход мимо правил первой линии |
| Сценария нет в окне смены | Предложение начать новую смену с этого тикета, с подтверждением | Вставить тикет сверх окна значило бы нарушить окно; новая смена — честный путь, но необратимый |
| Очки за курс | Нет | Оценка считает работу по тикету; курс — подготовка к ней |
| Значки | Значок за пройденный курс в профиле | Срез 5 отложил значки «до курсов»: без повода они украшение |

## Модель — `core/learning/`

```ts
type Block =
  | { kind: 'p'; text: string }          // абзац; `код` в обратных кавычках
  | { kind: 'code'; text: string }       // вывод или команды, моноширинно
  | { kind: 'list'; items: string[] }

interface Option { text: string; correct?: true; why: string }

type Check =
  | { id: string; kind: 'choice'; prompt: string; options: Option[] }
  | { id: string; kind: 'text'; prompt: string; accept: string[]; why: string;
      misses?: Array<{ answer: string; why: string }> }

interface Lesson  { id: string; title: string; body: Block[]; checks: Check[]; practice?: string }
interface Section { id: string; title: string; lessons: Lesson[]; quiz: Check[] }
interface Course  { id: string; title: string; summary: string; sections: Section[] }
```

- `why` у варианта — разбор: у неверного — почему неверен, у верного —
  почему верен. Показывается после ответа.
- Текстовая проверка сравнивает после нормализации: края обрезаны,
  регистр снят, пробелы схлопнуты. `misses` — известные неверные
  ответы с разбором (`ipconfig /renew` на вопрос про освобождение
  аренды); неизвестный неверный — «Не тот ответ» без разбора.
- `practice` — id сценария из библиотеки.
- Полный адрес проверки — `курс/секция/урок/проверка`, квиза —
  `курс/секция`. Адреса стабильны: по ним хранится прогресс.

### Загрузчик — `validateCourses(courses, scenarioIds)`

Бросает при запуске стора, как `validateScenarios`: id уникальны на
каждом уровне; у варианта выбора есть `why`; вариантов не меньше двух
и верный ровно один; у текстовой проверки есть `accept`; у урока есть
хотя бы одна проверка; у секции — хотя бы один урок и вопрос квиза;
`practice` называет существующий сценарий.

### Операции

- `checkAnswer(check, answer: number | string): { correct: boolean; why: string | null }`
- `gradeQuiz(quiz, answers): { score; total; passed; items: Array<{ id; correct; why: string | null }> }` —
  у несданного `why` только у неверных ответов, у сданного — у всех.
- `courseState(course, learning)` — статусы: секция `open | locked`,
  урок `done | open | locked`, квиз `passed | open | locked`, курс
  пройден ли. Всё выводится из прогресса, ничего не хранится
  вторым экземпляром — правило «счётчики выводятся из истории».
- `recordCheck`, `recordQuiz(learning, id, grade, at)`, `mergeLearning(loaded, inMemory)`.

### Прогресс

```ts
interface QuizResult { id: string; attempts: number; best: number; total: number; passedAt: string | null }
interface Learning  { checks: string[]; quizzes: QuizResult[] }
```

`Progress.learning: Learning`. Прогресс прошлого формата без поля
читается как «ничего не пройдено»; битое поле — ошибка проверки, как
битая статья. Гидратация сливает: проверки — объединением, квизы по id
— попытки складываются, лучший результат — максимум, дата сдачи —
первая. «Стереть прогресс» стирает и обучение.

## Стор

- `learnAt: { course: string; lesson?: string; quiz?: string } | null` —
  где остановился ученик; переживает переход к тикету и обратно.
- `answerCheck(course, lesson, check, answer)` — урок должен быть
  открыт (правило в сторе, а не в кнопке); верный ответ пишется в
  `learning.checks` синхронно, хранилище — следом.
- `submitQuiz(course, section, answers)` — квиз должен быть открыт;
  каждая попытка пишется.
- `practice(scenarioId, newShift = false): PracticeResult` —
  1. тикет сценария уже в работе — открыть его;
  2. в работе другой — `{ status: 'blocked', error: 'сначала завершите текущий тикет' }`;
  3. тикет сценария в окне смены — взять его (`claimTicket`);
  4. иначе без `newShift` — `{ status: 'needs-new-shift', lost }`, где
     `lost` — номера отложенных тикетов («Ждём поставку»), которые
     новая смена забудет; с `newShift` — новая смена, в пуле этот
     сценарий первым, тикет сразу взят.

## Интерфейс

- **«Курсы»** — инструмент после «Профиля». Список курсов с
  прогрессом («уроков 5 из 16, квизов 1 из 4»). Курс: секции с
  уроками и квизом, статус словом («пройден», «открыт», «закрыт —
  сдайте квиз „Сеть“»). Цвет — только у суждения: пройден/сдан и
  неверно.
- **Урок:** текст блоками, проверки с ответом и разбором, блок
  «Практика»: краткое описание тикета, «Взять тикет», последний
  результат по этому сценарию из истории. Подтверждение новой смены —
  на месте кнопки, «Отмена» первой (правило «необратимое не встаёт под
  курсор»).
- **Квиз:** все вопросы, «Сдать», результат с разбором, «Пересдать».
- **Профиль:** раздел «Обучение» — прогресс по курсам и значки.

## Курс «Первая линия»

| Секция | Уроки (практика) |
|---|---|
| Тикет и процесс | Владение тикетом (APIPA) · Сверка личности (блокировка) · Заметка о решении (APIPA) · Подтверждение и эскалация (ретрансляция) |
| Сеть | Читаем `ipconfig /all` (APIPA) · DHCP и самоназначенный адрес (APIPA) · VLAN и порт коммутатора (переезд) · Ретрансляция DHCP (ретрансляция) |
| Учётные записи | Блокировка и сброс пароля (блокировка) · Источник блокировки (блокировка) · Доступ через группы (папка отдела) · Билет входа (папка отдела) |
| Рабочее место и оборудование | Службы и журнал событий (диспетчер печати) · Диспетчер устройств (док-станция) · Гарантия, RMA и утилизация (гарнитура) · Ожидание поставки (док-станция) |

Тексты свои (требование 5), бренды — вымышленные из `brand.ts`, команды
и их вывод — те, что поддерживает тренажёр. Уроки учат способу, а не
разгадке конкретного тикета: номеров портов, имён и адресов из
сценариев в уроках нет.

## Тесты

- `learning`: разбор ответа — таблица литералов (выбор, текст с
  нормализацией, известный промах); квиз — порог, разбор несданного
  без верных ответов; статусы — цепочка открытия по мере прогресса;
  загрузчик — таблица испорченного контента; слияние.
- `validate`: прогресс без `learning` читается; битое — ошибка.
- стор: ответ в закрытом уроке — отказ; квиз пишется в хранилище;
  практика — таблица четырёх случаев.
- `e2e`: секция пройдена целиком через стор — открыта следующая;
  урок берёт свой тикет, тикет решён — урок показывает вердикт.
- бренды: курсы в списке сканируемых источников.
- настоящий курс проходит загрузчик — стор создаётся с ним.
