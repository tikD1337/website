# Срез 7Б — комната интервью: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** интервью на первую линию — знакомство, технические вопросы, ваш опыт, ваши вопросы, вердикт — с разбором по чек-листу, без модели и с ней.

**Architecture:** детерминированное ядро `core/interview/` ведёт ход и оценивает ответы по маркерам пунктов; трек — контент в `src/interviews/`. Разъём диалога получает метод `interview` с промптом интервьюера и той же деградацией; модель даёт только реакцию и ответы на вопросы кандидата. Результат ложится в `Progress.interviews`.

**Tech Stack:** TypeScript, React 18, zustand, vitest. Без новых зависимостей.

**Spec:** `docs/superpowers/specs/2026-09-30-slice-7b-interview-design.md`

## Global Constraints

- Ядро (`src/core/**`) — без React, `window`, `Date.now()` и случайности.
- Тексты по-русски, бренды — только из `src/brand.ts`; контент свой.
- Модели уходят только имя интервьюера, факты о компании, этап, текст вопроса и реплики — ни пунктов, ни маркеров, ни образцовых ответов.
- Пороги: уточнение — доля пунктов `< 0.5`; вердикт «Рекомендован» — технические `≥ 0.7`, опыт `≥ 0.5`, вопросов `≥ 1`; «Под вопросом» — технические `≥ 0.45`.
- Прочитанное из хранилища — `unknown`, пока не проверено; проверка не бросает.
- Тесты — по CLAUDE.md «Какие тесты писать». Не использовать `git add -A`.

## Review Focus

1. **Пустой ответ или ответ, пока интервьюер «думает»** — не записывается, ход не сдвигается. Тест — задача 7.
2. **Ответ с другим регистром, `ё`, лишними пробелами** — маркеры находятся. Тест — задача 1.
3. **В истории только проваленные тикеты** — вопрос об опыте общий, а не по проваленному сценарию. Тест — задача 2.
4. **Вопрос кандидата мимо всех заготовок** — нейтральный ответ, а не молчание. Тест — задача 2.
5. **Интервью брошено и начато заново, пока модель отвечала** — старый ответ не попадает в новое интервью. Тест — задача 7.

### Task 2: Ход интервью

**Interfaces:**
- Consumes: задача 1.
- Produces: `interface Solved { scenarioId: string; summary: string }`; `startInterview(track: InterviewTrack, attempt: number, solved: Solved[]): InterviewRun` — план `[intro, …технические, опыт]`, стенограмма `[greeting, prompt(intro)]`; `questionText(track, run, id): string` — подставляет `{тикет}` («тикет „<summary>“»); `answer(track, run, text): { run: InterviewRun; next: string | null }` — чистая, ответ кандидата в стенограмме, `next` — уточнение, следующий вопрос или `track.yourQuestions`, `null` после этапа вопросов; `say(run, text): InterviewRun` — реплика интервьюера; `askInterviewer(run, text): InterviewRun`; `faqReply(track, said): string` (совпадение `similarity` из `dialogue/scripted`, порог `0.5`, иначе `FAQ_FALLBACK = 'Это лучше обсудить на следующем этапе, с командой.'`); `reaction(n: number): string` — по кругу `['Понятно.', 'Хорошо, спасибо.', 'Принято.', 'Ясно, спасибо.']`; `finishQuestions(run): InterviewRun`; `gradeInterview(track, run): InterviewResult` — доли: знакомство, среднее технических, опыт; `questionsAsked`; вердикт `verdictFor`.

## Что нашлось по ходу

Дефекты, которых план не предусмотрел:

1. **Маркер после чередования не ловит форму слова.** «освобод» не
   находит «освобождаю» (д/ж). Маркеры трека — основы до чередования;
   правило записано в комментарии трека (задача 1).
2. **Маркер из текста самого вопроса засчитывал пункт за пересказ.**
   Общий вопрос об опыте спрашивал «чем подтвердили», а «подтверд» был
   маркером пункта «чем подтвердили» — у всех восьми вопросов об опыте.
   Появился тест трека «маркеры не повторяют слов вопроса»; вопросы
   переформулированы (задача 4).
3. **Общий маркер «нет»** засчитывал отказ от RMA в ответе «отправлю
   вендору, хотя гарантии нет». Убран (задача 4).
4. **Факты о компании подсказывали ответы.** «Передача через тикет с
   доказательствами» и «оценивают заметку, подтверждение заявителя…»
   уходили модели в каждом промпте и отвечали на вопросы об эскалации
   и заметке. Поймал тест утечки; факты переписаны (задача 5).
5. **Циклический импорт `grade` ↔ `flow`.** Поиск вопроса и его текст
   вынесены в `questions.ts` (задача 2).
6. **Полоса этапов слиплась** в «Знакомство2. Рабочие ситуации»: у
   гибкого списка номер рисуется снаружи и налезает на соседний пункт
   (визуальная проверка, задача 8).
7. **Пункты разбора шли «сначала прозвучавшие»**, а не в порядке
   вопроса — разбор не читался как чек-лист (визуальная проверка,
   задача 8).

Проверено в браузере без модели: интервью целиком — знакомство, пять
ситуаций с уточнением на первой, общий вопрос об опыте (истории нет),
вопрос из заготовок и мимо них, разбор «Рекомендован», 95 % по
ситуациям; перезагрузка — попытка в истории; вторая попытка начинается
с шестого вопроса пула; «Прервать интервью» — фокус на «Продолжить»,
запись не создаётся; профиль показывает последний вердикт. 1400×860 и
900×700 — ничего не вылезает, ошибок в консоли нет.

Пробелы, оставленные намеренно:

- Накачка ответа маркерами не ловится — решение спеки.
- Живой проверки с моделью в облаке нет: Ollama здесь не запущена;
  реакция модели покрыта тестом разъёма на моке и проверкой утечки.

## Решения исполнителя

- Задача 1: маркер фикстуры «освобод» → «освобо» — основы до
  чередования. Цена — нулевая.
- Задача 2: `questionById`/`questionText` — в `questions.ts`, не в
  `flow.ts`: цикл импортов. Цена — лишний файл.
- Задача 4: тест «маркеры не повторяют слов самого вопроса» — правило
  было только в тексте плана. Цена — один тест.
- Задача 4: маркер «нет» убран у пункта «не отправлять вендору». Цена —
  короткое «нет» пункта не даёт.
