# Дорожная карта: срезы 2–8

> Разбивка по задачам без пошагового кода. Пошаговый код с тестами
> пишется отдельным планом **перед началом каждого среза** — иначе он
> опирается на интерфейсы, которых ещё нет, и устаревает раньше, чем
> до него дойдут руки.
>
> Спека: `../specs/2026-09-09-helpdesk-simulator-design.md`
> Срезы 0–1: `2026-09-09-helpdesk-simulator-slice-0-1*.md`

Правило, общее для всех срезов: **каждый заканчивается состоянием, в
которое можно играть**, и ни один не добавляет инструмент, не подключив
его к единому состоянию мира и к оценке.

---

## Срез 2 — рабочий стол удалёнки

Сейчас удалёнка это текстовое поле. Здесь она становится тем, чем должна
быть: симуляцией Windows.

| Задача | Что делает | Готово, когда |
|---|---|---|
| 2.1 Оконный менеджер | Перетаскивание, z-порядок, свернуть/развернуть/закрыть, панель задач | Два окна открываются, перекрываются, поднимаются кликом |
| 2.2 Рабочий стол | Обои, иконки, файлы пользователя, двойной клик, меню «Пуск», поиск | Командная строка открывается с десктопа и с панели задач |
| 2.3 Системный трей | Иконки сети, безопасности, громкости, часы — **читают состояние мира** | Починка адреса в терминале сама меняет иконку сети |
| 2.4 Терминал как окно | Перенос `TerminalView` внутрь оконного менеджера, история, `cls` | Терминал ведёт себя как окно, а не как страница |
| 2.5 Просмотр событий | Журналы System/Application, уровни, коды, источники — из `device.eventLog` | Сценарий может «положить» запись в журнал, и она видна |
| 2.6 Службы | Список, статус, тип запуска, старт/стоп через шлюз полномочий | Остановка службы пишется в журнал изменений |
| 2.7 Диспетчер устройств | Дерево, коды проблем, состояние драйверов | Драйвер с проблемой виден и в GUI, и в `driverquery` |
| 2.8 Панель RDP | Ctrl+Alt+Del, буфер обмена, полный экран, отключиться | Отключение возвращает в список машин |

**Ключевое требование среза:** каждое окно читает и пишет то же
`WorldState`, что и терминал. Ни одно окно не хранит своё состояние.

## Срез 3 — каталог и учётные записи

| Задача | Что делает |
|---|---|
| 3.1 Дерево OU | Домен → Corp → Employees по отделам, Workstations, ServiceAccounts, Servers, Groups, Admin с Tier0 |
| 3.2 Свойства объекта | Двойной клик открывает карточку: общие, учётная запись, членство в группах |
| 3.3 Операции над учёткой | Разблокировать, сбросить пароль, включить/выключить — **все через `authorize`** |
| 3.4 Проверка личности | Диалог сверки с карточкой каталога; поднимает `identityVerified` |
| 3.5 Команды каталога | `net user`, `net group`, `net localgroup`, `dsquery`, `whoami` |
| 3.6 Сценарии identity | Блокировка, истёкший пароль, отсутствие в нужной группе, доступ к общей папке |

**Ловушка, которую нужно сохранить:** сброс пароля без подтверждённой
личности должен быть **возможен технически** и наказан оценкой — иначе
тренажёр не учит границе, а просто её прячет.

## Срез 4 — люди

Здесь появляется собеседник и замыкается петля подтверждения.

| Задача | Что делает |
|---|---|
| 4.1 Разъём диалога | Интерфейс `DialoguePort`, реализация «сценарий» по умолчанию |
| 4.2 Телефон | Диалер со справочником, свой обратный номер, лента звонка |
| 4.3 Персона | Отдаёт только `persona.knows`; **корневая причина не передаётся никогда** |
| 4.4 Почта и чат | Переписка по тикету, единая лента общения в карточке |
| 4.5 Клиент OpenAI-совместимого API | Один клиент, конфиг `baseUrl` / `apiKey` / `model` |
| 4.6 Экран настроек | Переключение «сценарий / локальная модель / свой эндпоинт» на лету |
| 4.7 Деградация | Модель недоступна → откат на реплики с плашкой, без падения |
| 4.8 Синтез речи | `speechSynthesis`, позже локальный нейронный синтез |
| 4.9 Распознавание речи | Локальное распознавание; ввод текстом всегда доступен как запасной |
| 4.10 Прокси dev-сервера | `/api/llm`, ключ в локальном конфиге вне git |

**Проверка среза:** выдернуть сеть и выключить модель — тренировка
должна продолжаться без единой ошибки в консоли.

## Срез 5 — прогрессия

| Задача | Что делает |
|---|---|
| 5.1 Сохранение | IndexedDB: профиль, история тикетов, счётчики; настройки в localStorage |
| 5.2 Очки и ранги | Начисление по вердикту, пороги рангов, недельный счётчик |
| 5.3 Счётчики | Закрыто, без ошибок, серия, активные и тихие поломки |
| 5.4 История тикетов | Список с вердиктом, очками и ссылкой на разбор |
| 5.5 Профиль | Сводка по шести измерениям за последние N тикетов — что проседает |
| 5.6 Генератор очереди | Догенерация тикетов при закрытии, скрытие тикета без штрафа |
| 5.7 Лидерборд | Локальный: ваши прошлые прохождения против нынешнего |

**Отличие от оригинала:** глобального лидерборда не будет — играет один
человек. Вместо него сравнение с собой прошлым, что для тренировки полезнее.

## Срез 6 — инфраструктура и вещи

| Задача | Что делает |
|---|---|
| 6.1 Серверная | Коммутаторы, роутеры, серверы, принтеры; вкладки общее/здоровье/диагностика |
| 6.2 CLI коммутатора | Порты, VLAN, состояние линка, DHCP-релей |
| 6.3 Область тикета | Изменения инфраструктуры проверяются против тикета — расширение `authorize` |
| 6.4 CMDB | Активы: тег, тип, вендор, владелец, жизненный цикл, место, гарантия |
| 6.5 Логистика | Типы отправлений, направление, привязка к активу и тикету |
| 6.6 Таймер отправлений | Статус двигается по времени; тикет ждёт и возобновляется |
| 6.7 База знаний | Пустая на старте, наполняется закрытыми тикетами; типы, статус, версия |
| 6.8 Публикация при закрытии | Заметки и код закрытия превращаются в черновик статьи |

**Смысл 6.7–6.8:** база знаний не пишется автором — она зарабатывается
игроком. Это снимает изрядную часть работы по контенту и, что важнее,
делает документацию осмысленной: вы читаете то, что писали сами.

## Срез 7 — обучение

| Задача | Что делает |
|---|---|
| 7.1 Движок уроков | Секции, уроки, проверки внутри урока, последовательное открытие |
| 7.2 Квизы секций | Вопросы с разбором неверных вариантов |
| 7.3 Связь с практикой | Урок ссылается на тренировочный тикет и открывает его |
| 7.4 Комната интервью | Структура: знакомство → вопросы → ваш опыт → ваши вопросы → вердикт |
| 7.5 Разбор интервью | Что показано, чего не хватило, какой ответ ждали |

Интервью использует тот же разъём диалога, что и телефон. Без модели —
режим с готовыми вопросами и разбором по чек-листу.

## Срез 8 — контент

Самый длинный и самый ценный. Здесь нет архитектуры, есть работа.

Девять категорий: **identity · networking · Windows desktop · software ·
hardware · printers · mobile · security · infrastructure**.

Порядок написания — по тому, что уже поддержано движком:

1. **networking** (движок готов после среза 1): DNS указывает на мёртвый
   сервер, нет шлюза, дубль адреса, VPN не поднимается, медленный линк
2. **identity** (после среза 3): блокировки, истёкшие пароли, группы,
   доступ к общим папкам, кэшированные учётные данные на телефоне
3. **Windows desktop** (после среза 2): службы, драйверы, диск, обновления,
   профиль не загружается
4. **printers, hardware, software, mobile, security, infrastructure** —
   по мере готовности соответствующих инструментов

**Правило качества сценария**, выведенное из разбора оригинала: у каждого
сценария должна быть **развилка, на которой очевидный шаг не срабатывает**.
Именно она отличает тренировку от инструкции. В APIPA это `renew`, который
падает, пока не сделан `release`.

**Правило вариативности:** адреса, имена и машины в инъекции
параметризуются, суть поломки — нет. Иначе библиотека заучивается.

## Порядок и зависимости

```
срез 1 ──┬─► срез 2 (рабочий стол) ──┬─► срез 6 (инфраструктура)
         │                            │
         ├─► срез 3 (каталог) ────────┤
         │                            │
         ├─► срез 4 (люди) ───────────┴─► срез 7 (обучение)
         │
         └─► срез 5 (прогрессия)

срез 8 (контент) идёт параллельно, начиная сразу после среза 1
```

Срезы 2, 3, 4 и 5 независимы друг от друга — их можно делать в любом
порядке или чередовать с написанием сценариев.

## Что уйдёт больше всего времени

| | Оценка |
|---|---|
| Срезы 2–7 (движок и инструменты) | недели |
| Срез 8 (контент) | месяцы |

Это не пессимизм, а арифметика: у ориентира 72 сценария и 10 курсов
примерно по 68 проверок. Сценарий стоит тридцать строк **только после**
того, как движок его поддерживает; до этого он стоит нового инструмента.

Поэтому срез 1 сделан так, чтобы играть можно было задолго до того, как
контент будет готов.
