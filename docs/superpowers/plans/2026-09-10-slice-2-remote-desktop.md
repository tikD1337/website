# Срез 2: рабочий стол удалёнки

> **Для агентов-исполнителей:** ОБЯЗАТЕЛЬНЫЙ ПОД-SKILL —
> `superpowers:executing-plans`. Шаги размечены чекбоксами.

**Цель:** удалёнка перестаёт быть текстовым полем и становится симуляцией
рабочего стола: окна, панель задач, трей, читающие то же состояние мира.
На выходе — второй играбельный сценарий, который **нельзя решить одним
терминалом**.

**Спека:** `../specs/2026-09-09-helpdesk-simulator-design.md`
**Предыдущий срез:** `2026-09-09-helpdesk-simulator-slice-0-1*.md`

## Глобальные ограничения

Те же, что в срезе 1, плюс:

- Ядро (`src/core/**`) по-прежнему без React, без `window`, без `Date.now()`.
- **Каждое окно читает и пишет `WorldState`.** Собственного состояния окно
  не хранит — иначе связность, ради которой всё построено, развалится.
- Каждая новая операция изменения проходит через `authorize`.
- Вывод команд сверяется с живой Windows, как в срезе 1.
- `git add` только явными путями: в `E:\site` живёт посторонний `screensaver/`.

---

## Решение о глубине моделирования

Соблазн — завести под каждое окно отдельную структуру. Это ошибка: тогда
`sc stop spooler` в терминале и остановка службы мышью окажутся разными
кодовыми путями, и рано или поздно разойдутся.

**Правило: окно — это представление, команда — это тоже представление.
Операция одна.** Останов службы живёт в `core/device/services.ts` и
вызывается обоими. Тест на это обязателен в каждой задаче, где операция
доступна двумя путями.

### Задача 1: Расширить модель устройства

**Файлы:** `src/core/world/types.ts`, `seed.ts`, тест `world.test.ts`

Добавить в `Device`: `services[]`, `processes[]`, `eventLog[]`, `drivers[]`,
`disks[]`. Поля — по спеке, раздел 3.1.

Наполнить seed правдоподобно: полтора десятка служб с реальными именами
(`Spooler`, `Dnscache`, `Dhcp`, `WinDefend`, `wuauserv`…), десяток записей
журнала, диски, драйверы.

- [ ] Тест: у каждой машины непустые службы, журнал, диски
- [ ] Тест: имена служб уникальны в пределах машины
- [ ] Тест: `cloneWorld` копирует новые поля глубоко
- [ ] Реализация, зелёные тесты, коммит

### Задача 2: Операции над устройством

**Файлы:** `src/core/device/services.ts`, `eventlog.ts`, тесты

Единственное место, где меняются службы и пишется журнал.

```
startService(world, host, name, session, clock) → Result
stopService(world, host, name, session, clock)  → Result
setStartType(world, host, name, type, ...)      → Result
appendEvent(world, host, entry)                 → void
```

Каждая операция: проверяет существование, идёт через `authorize`, пишет
`recordChange`, **и добавляет запись в журнал событий машины** — как
настоящая Windows.

- [ ] Тест: остановка службы меняет статус и пишет изменение в журнал сессии
- [ ] Тест: остановка защитной службы (`WinDefend`) отклоняется шлюзом
- [ ] Тест: операция добавляет запись в `eventLog` устройства
- [ ] Тест: несуществующая служба даёт внятную ошибку

### Задача 3: Команда sc

**Файлы:** `src/core/terminal/commands/sc.ts`, тест

`sc query`, `sc queryex`, `sc start`, `sc stop`, `sc config`.
Вывод сверить с живой Windows (`sc query spooler`).

- [ ] Тест: формат вывода совпадает с эталоном
- [ ] **Тест: `sc stop spooler` и `stopService` дают одинаковое состояние мира**
- [ ] Тест: `sc stop windefend` возвращает отказ доступа

### Задача 4: Оконный менеджер

**Файлы:** `src/store/windows.ts`, `src/ui/desktop/WindowManager.tsx`,
`Window.tsx`, тест `windows.test.ts`

Состояние окон живёт **отдельно от `WorldState`** — это состояние
интерфейса, а не мира: какое окно открыто и где оно лежит, к инциденту
отношения не имеет.

```
openWindow(id) · closeWindow(id) · focusWindow(id)
moveWindow(id, x, y) · minimize(id) · toggleMaximize(id)
```

- [ ] Тест: открытие поднимает окно наверх по z-порядку
- [ ] Тест: фокус переносит окно наверх, не меняя порядок остальных
- [ ] Тест: повторное открытие не создаёт второе окно
- [ ] Компонент: перетаскивание за заголовок, кнопки свернуть/развернуть/закрыть
- [ ] Клавиатура: Esc закрывает сфокусированное окно, focus-visible виден

### Задача 5: Рабочий стол, панель задач, трей

**Файлы:** `src/ui/desktop/Desktop.tsx`, `Taskbar.tsx`, `Tray.tsx`, стили

Иконки на десктопе, кнопка «Пуск», панель задач с открытыми окнами,
трей с часами и иконками сети/безопасности.

**Иконки трея читают состояние мира** — это самая дешёвая и самая
заметная демонстрация связности, ровно как в оригинале.

- [ ] Тест: иконка сети показывает «нет подключения» при самоназначенном адресе
- [ ] Тест: после починки иконка меняется
- [ ] Часы берут время из инжектируемых часов, а не из `Date.now()`

### Задача 6: Терминал как окно

**Файлы:** правка `TerminalView.tsx` → `src/ui/apps/CommandPrompt.tsx`

Перенести существующий терминал внутрь оконного менеджера. Поведение и
тесты сохранить, добавить `cls`.

- [ ] Все прежние тесты терминала по-прежнему зелёные
- [ ] Терминал открывается с иконки и с панели задач

### Задача 7: Просмотр событий

**Файлы:** `src/ui/apps/EventViewer.tsx`

Журналы System и Application, уровни, коды, источники, время. Читает
`device.eventLog`.

- [ ] Тест: запись, добавленная операцией из задачи 2, видна в окне
- [ ] Фильтр по уровню, сортировка по времени

### Задача 8: Службы и диспетчер устройств

**Файлы:** `src/ui/apps/Services.tsx`, `DeviceManager.tsx`

Список служб со статусом и типом запуска, старт/стоп через операции из
задачи 2. Дерево устройств с кодами проблем.

- [ ] **Тест: остановка мышью и `sc stop` неотличимы по итоговому состоянию**
- [ ] Тест: попытка остановить защитную службу показывает отказ, а не прячет кнопку

### Задача 9: Сценарий, требующий GUI

**Файлы:** `src/scenarios/print-spooler-stopped.ts`

Принтер не печатает. Причина — служба диспетчера печати остановлена и
переведена в «отключено». В журнале событий есть запись о сбое.

Ключевое: **сценарий нельзя закрыть одним терминалом честно** — нужно
посмотреть журнал событий, чтобы понять, почему служба упала, иначе
техник просто перезапустит её и получит повтор через день.

- [ ] Цели включают чтение журнала событий
- [ ] Тихая поломка: запустил службу, но не вернул тип запуска в «авто»
- [ ] Сквозной тест: образцовое прохождение даёт `full`
- [ ] Сквозной тест: перезапуск без чтения журнала даёт `partial`
- [ ] Сквозной тест: оставленный тип «отключено» даёт тихую поломку

## Что этот срез намеренно не делает

Проводник, браузер, параметры, VPN-клиент, портал ПО — иконки на десктопе
будут, содержимого не будет. Они нужны сценариям срезов 4–6; делать их
сейчас — работа без потребителя.

## Проверка среза

- Все тесты среза 1 по-прежнему зелёные
- Два сценария в очереди, второй требует GUI
- Иконка трея меняется от команды в терминале
- `npm run build` проходит
