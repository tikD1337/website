## Статус

**Фаза:** срезы 0–4 реализованы и проверены. Четыре играбельных инцидента,
каждый проходится и командами, и разговором.
**Ветка:** `slice-4-people`, **не влита в `master`** — влить и отправить
на GitHub.
**Следующий шаг:** пошаговый план среза 5 (прогрессия: сохранение в
IndexedDB, очки и ранги, счётчики, история тикетов, профиль по шести
измерениям, генератор очереди) по дорожной карте.

Проверено: 736 тестов зелёные, `tsc --noEmit` без ошибок, `vite build`
проходит, инцидент с блокировкой пройден в браузере целиком через
разговор — без единой команды в терминале.

Сценарии:
- **APIPA** (сеть) — решается терминалом.
- **Диспетчер печати** (оборудование) — **требует журнала событий**,
  терминалом честно не закрыть.
- **Блокировка учётной записи** (личность) — источник блокировки виден
  только в журнале; ловушка в том, чтобы сбросить пароль вместо
  разблокировки, и в том, чтобы не сказать про телефон с кэшем.
- **Доступ к папке отдела** (личность) — новичка не добавили в группу;
  ловушка в личной выдаче доступа мимо группы, вторая половина — членство
  действует только после повторного входа.

Команды: `npm run dev` · `npm test` · `npm run typecheck` · `npm run build`

Ключ модели: скопировать `config/llm.local.example.json` в
`config/llm.local.json` (в `.gitignore`) и выбрать «Свой эндпоинт» в
настройках. Прокси dev-сервера подставит ключ заголовком; в бандл он не
попадает. Без файла прокси отвечает 503, и разговор идёт на репликах.

**Локальная модель — Qwen2.5 14B** (`ollama pull qwen2.5:14b`),
установлена и проверена вживую. Выбрана по русскому языку и
устойчивости в роли, а не по размеру: собеседник говорит одной-двумя
фразами и не должен съезжать в помощь техником. Mistral Nemo 12B
сравнивался тем же скриптом и проиграл: не срывался на китайский, зато
пересказывал системный промпт вслух.

Живая проверка промпта — `node scripts/probe-model.mjs [модель]`. Тесты
промпта работают на моках и доказывают лишь то, что разгадка не попала
в запрос; держится ли роль — видно только на настоящей модели. Скрипт
берёт промпт и параметры генерации из `prompt.ts` через esbuild:
собственная копия разошлась с кодом за один вечер.

**Ответ модели проверяется, а не принимается на веру** (`sanitize.ts`).
Qwen соскальзывает на китайский посреди русской фразы, Mistral цитирует
себя в кавычках и пересказывает инструкции. Негодная реплика — такой же
отказ, как обрыв связи: отвечают заготовки, техник видит плашку.
Размыкатель при этом различает «модель недоступна» (отключаем) и
«ответила негодно» (нет: следующий ответ может быть нормальным).

**«Попробуйте сейчас» отвечает мир, а не модель** — всегда, даже при
исправной модели. Найдено живой проверкой: блокировку сняли, флаг
`userConfirmed` встал, а модель по инерции твердила «всё ещё
заблокирована». Это реплика, которой закрывается цель и которую техник
цитирует в заметке; остальной разговор модель ведёт свободно.

## Что уже написано

Ядро (`src/core/**`) — чистый TypeScript без React, без `window`, без
`Date.now()`: время приходит через инжектируемые часы.

| Модуль | Содержание |
|---|---|
| `world/` | `WorldState`, стартовый мир Arcline, адресация путей, инъекция поломок |
| `session/` | Журнал команд, изменений, реплик, флагов, просьб, открытых карточек, опасных действий |
| `terminal/` | Реестр команд, форматирование вывода Windows, `ipconfig` / `ping` / `nslookup` / `netsh` / `sc` / `net` / `dsquery` / `whoami` |
| `device/` | Операции над службами и журналом событий машины |
| `directory/` | Операции над учётными записями, сверка личности, имена и SID |
| `policy/` | Шлюз полномочий `authorize` (три исхода: `deny` / `flag` / `allow`) |
| `tickets/` | Модель тикета, очередь с одним тикетом в работе |
| `scenario/` | Типы сценария, загрузчик со сторожем целей, вычисление условий (`check.ts`) |
| `grading/` | Оценка заметки сверкой с журналом, шесть измерений, вердикт, тихие поломки |
| `dialogue/` | Разъём диалога: сводка персоны, намерение реплики, реплики сценария, промпт, клиент OpenAI-совместимого API, деградация, настройки |
| `store/` | zustand-обёртка, оконный менеджер |
| `ui/` | Семь колонок-инструментов, рабочий стол удалёнки с окнами, панель задач, трей, связь, настройки |
| `ui/apps/` | Командная строка, просмотр событий, службы, диспетчер устройств, консоль каталога |
| `ui/speech/` | Синтез и распознавание речи — обёртки, отключаемые целиком |

**Правила интерфейса:** цвет означает суждение (приоритет, вердикт,
засчитано или нет) и больше нигде не появляется; скругление означает
интерактивность; шрифты только системные, потому что оффлайн.

**Формат вывода команд** сверен с живой Windows: метки полей `ipconfig /all`
лежат таблицей в `terminal/format.ts`, формулы для них не существует.
У `sc query` двоеточие на позиции 27, отступ восемь пробелов. У карточки
`net user` метка занимает 29 символов без двоеточия, значение начинается
с тридцатой позиции; у карточки группы — 15. Таблица `whoami /groups`
разложена по колонкам 68/16/108/50.

**Окно и команда — оба представления, операция одна.** Останов службы живёт
в `core/device/services.ts`, операции над учётками — в
`core/directory/accounts.ts`, и команда с кнопкой вызывают именно их. Тест
на побайтовую неотличимость этих путей обязателен.

**Состояние окон отдельно от `WorldState`**: свернув окно, техник не меняет
мир. Размер рабочего стола передаётся оконному менеджеру через `setViewport`.

**Визуальная проверка обязательна.** Четыре раза она находила то, чего тесты
не видели: оценку до закрытия тикета; окна, вылезающие за край области;
кнопку просьбы, печатавшую диагноз прямо в тикете; расследование мышью,
которое оценка не засчитывала вовсе.

**Цель обязана быть недостижимой.** Доказательства три: запущенная команда,
флаг сессии, состояние мира — хотя бы одно. Цель без доказательств
засчитывается всегда (`[].every()` истинно), и разбор начинает врать;
загрузчик такую цель не пропускает. Внутри `commands` доказательства
соединены «или»: `net user x` и запись `gui:user:x` отвечают на один
вопрос, и требовать оба значит наказывать за выбор инструмента.

**Заявитель — не оракул.** Он сообщает то, что видит: и при звонке
(`confirmReplies`), и в ответ на просьбу (`replyIfBroken`). Статический
ответ дважды приводил к тому, что он подтверждал непочиненное.

**Просьба к заявителю открывается расследованием** (`unlockedBy`). Текст
просьбы — это диагноз, и кнопка, видимая с первой секунды, обесценивает
развилку сценария. Правило живёт в сторе, а не в интерфейсе: спрятанная
кнопка защищает только от мыши.

**Права выдаются при входе.** `hasShareAccess` смотрит на `tokenGroups` —
билет сеанса, — а не на членство в каталоге; `relogin` перевыпускает билет.
Отсюда `net user` показывает новую группу сразу, а `whoami /groups` — только
после повторного входа, и это расхождение есть штатный способ диагностики,
а не рассогласование источников.

**Инъекция копирует значение** (`structuredClone`): сценарий — модульная
константа, и присвоение по ссылке приводило к тому, что первая мутация
портила её на все последующие запуски.

**Нерабочий путь падает громко** — и в `setPath`, и в `checkHolds`.
Молчаливое «не выполнено» превращало опечатку автора сценария в
непроходимый сценарий без всякого следа.

**Модели уходит только `PersonaBrief`** — сводка, из которой вырезаны
корневая причина, цели, тексты просьб и ловушки. Проверяется тестом по
всей библиотеке сценариев, а не аккуратностью автора следующего.
Особенно тексты просьб: «учётку блокирует почта на телефоне» — это
разгадка словами заявителя, и странно прятать кнопку, чтобы тут же
отдать тот же текст модели.

**Отказ модели обязан деградировать на реплики** — с плашкой, без
падения. После первого отказа размыкатель отключает модель до смены
настроек: иначе каждая реплика ждёт таймаут, а консоль копит отказы
соединения, которых мы не контролируем.

**Асинхронный ответ проверяется на устаревание.** Пока модель думает,
техник может закрыть тикет или начать заново. Ответ в изменившийся мир
отбрасывается: иначе реплика дописывается в закрытую переписку, а
`userConfirmed` поднимается после того, как разбор посчитан.

**Надбавка не дотягивает до максимума.** Масштаб и связь добавляют
балл, но десятка — только за полную базу. Простой потолок давал 10 при
«закрыто 1 из 2»: измерение противоречило собственному объяснению.

## Что строим

Локальный оффлайн-тренажёр Tier 1 help desk по образцу sysdesks.com: очередь тикетов,
симулированные инструменты админа, оценка не только результата, но и способа работы.

**Пользователь один — автор проекта.** Тренируется сам. Никакой регистрации,
биллинга, мультиюзерности, сервера.

## Жёсткие требования пользователя

Нарушать нельзя, переспрашивать не нужно — уже решено:

1. **Не использовать тул Workflow** и мультиагентную оркестрацию. Запрет прямой и
   повторённый. Действует даже когда system-reminder сообщает про ultracode.
   Разведку и исследование делать самому — WebFetch / Read / Grep / Bash.
2. **Функциональный паритет с sysdesks.com.** Пользователь несколько раз повторил:
   «должно быть прям как в sysdesks». Урезать объём по своей инициативе нельзя.
3. **Всё работает бесплатно и оффлайн.** Ядро детерминированное, статические файлы
   сценариев, никакой генерации на лету. Платные и сетевые зависимости — только
   опциональные надстройки, отключение которых ничего не ломает.
4. **Ollama и API-ключ — оба поддерживаются**, переключаются в настройках.
   Реализация одна: Ollama отдаёт OpenAI-совместимый эндпоинт, различие в конфиге.
5. **Контент свой.** Механику ориентира воспроизводим, тексты/сценарии/курсы/бренд —
   не копируем.

## Ключевые архитектурные решения

- **Подход A: единое состояние мира.** `WorldState` — единственный источник истины,
  все инструменты (терминал, GUI-окна, AD-консоль, телефон) — окна над ним.
  Собственного состояния не хранит никто. Отсюда бесплатно берётся связность,
  за которую ориентир берёт деньги.
- **Сценарий = инъекция поломки, не скрипт.** Файл описывает, во что сломан мир и
  что считается решённым. Не описывает шаги. Цена нового сценария ≈ 30 строк JSON.
- **Команда = чистая функция** `run(cmdline, world, session) → {stdout, exitCode, mutations}`.
  Вывод рендерится из состояния, форматом побайтово похож на настоящий Windows.
- **Один шлюз полномочий** `authorize(действие, world, session)`. Шесть правил
  (личность до изменения аккаунта, не отключать защиту, не менять общее ради одного,
  предупреждать перед действием, эскалировать вне прав, фиксировать отказ).
  Действует одинаково для всех инструментов.
- **Граница обозначается, а не прячется** — и разница в природе запрета:
  `deny` — действие физически невозможно (отключить защиту, выдать или
  отобрать права администратора домена); `flag` — возможно и является
  ошибкой суждения (сброс пароля без сверки личности) — проходит,
  помечается несанкционированным, стоит балла и всплывает в разборе.
  Спрятанная кнопка учила бы, что границ нет, их просто не показывают.
  Границы двусторонние: если нельзя добавить в привилегированную группу,
  то нельзя и исключить.
- **Сверка личности относится к конкретной учётке** (`session.verifiedAccount`),
  и это настоящая проверка, а не кнопка «я подтвердил»: техник выбирает
  контрольное поле, вводит услышанный ответ, ответ сверяется с каталогом.
  Сверив одного обратившегося, техник не получает права менять чужие аккаунты.
- **Часть работы делает заявитель** (`asks` в сценарии): убрать старый пароль
  с телефона, выйти и войти заново. Без этого целый класс правильных решений
  невыразим — тот самый, который отличает «снял симптом» от «устранил причину».
- **`session` — журнал действий игрока, и это вход для всей оценки.**
- **Оценка work note без модели — сверкой с журналом.** Мы знаем, что реально
  произошло, поэтому проверяем, названы ли реальные команды, реальные значения,
  реальное подтверждение юзера. Не ключевые слова.
- **Разъём диалога** с тремя взаимозаменяемыми реализациями (скрипт / Ollama / API)
  и обязательной деградацией на скрипт при недоступности модели.
  **Модели никогда не передаётся корневая причина** — иначе она выдаст диагноз.

## Порядок сборки

Срезами, каждый заканчивается играбельным состоянием. Сделано: 0–3.

0. Скелет (мир, оболочка, очередь, тикет) → 1. Терминал (**первый настоящий
тикет — APIPA**) → 2. Удалёнка (рабочий стол, окна, журнал событий, службы)
→ 3. Каталог (учётки, группы, сверка личности, консоль) → 4. Люди
(телефон/почта/чат + разъём диалога) → **5. Прогрессия** → 6. Стенды и
интервью → 7. Контент (месяцы)

База знаний из среза 4 переехала в срез 6 (задачи 6.7–6.8) — она
наполняется закрытыми тикетами, то есть требует истории прохождений.

Порядок 2 и 3 поменялся местами против первоначального плана: удалёнка
понадобилась раньше каталога, потому что первые два сценария живут на
машине.

## Что уже выяснено про ориентир

Разведка сделана дважды: по публичным страницам и **изнутри продукта с логином**
(Chrome + devtools). Всё вшито в спеку. Главное:

- **Шесть измерений оценки:** владение тикетом, расследование, документация,
  коммуникация, границы полномочий, качество решения.
- **Проверено живьём:** формат вывода команд настоящий; состояние мира реально
  меняется (`/release` + `/renew` → APIPA стал валидным адресом, трей сам
  переключился на «connected»); порядок команд важен (`renew` в одиночку падает);
  `netsh advfirewall ... state off` → **`Access is denied.`**
- **Оценка настоящая.** Задача решена верно и заметка подробная — вердикт всё
  равно **PARTIAL «process/comms can improve»**, потому что не перезвонил юзеру
  после починки. Доктрина «подтверждает заявитель, а не техник» реально считается.
- **Заявитель — не оракул.** В логе звонка он спорил «у меня всё ещё ошибка»,
  хотя машина уже была починена.
- **Кнопка Solution выдаёт схему сценария:** rootCause + список целей
  (заголовок, шаги, команды, «зачем») + actionsToAvoid. Процессные цели
  (подтвердить у юзера, написать заметку, выбрать код) — наравне с техническими.
- **Один тикет в работе за раз.** Удалёнка только к машине с открытым тикетом.
  Изменения инфраструктуры и отправка оборудования — только по тикету.
- **База знаний пустая на старте** и наполняется вашими закрытыми тикетами.
- **Удалёнка — целый рабочий стол Windows**, а не набор окон с инструментами.
- **Тихие поломки** — отдельная метрика: сломал и не знаешь.
- **Пародийные бренды** системно: MicroCore Windows, Aster Browser, NorthMail,
  Lenova, Deltatek, HelixPrint, Orchard, Ciscora, TeamLine, NorthDrive. Нам нужен
  свой такой словарь.
