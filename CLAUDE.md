Сценарии:
- **APIPA** (сеть) — решается терминалом.
- **Диспетчер печати** (оборудование) — **требует журнала событий**,
  терминалом честно не закрыть.
- **Блокировка учётной записи** (личность) — источник блокировки виден
  только в журнале; ловушка в том, чтобы сбросить пароль вместо
  разблокировки, и в том, чтобы не сказать про телефон с кэшем.
- **Доступ к папке отдела** (личность) — новичка не добавили в группу;
  ловушка в личной выдаче доступа мимо группы, вторая половина — членство
  действует только после повторного входа.
- **Переезд в чужой VLAN** (сеть) — розетка нового стола в VLAN принтеров,
  подписана от принтера; `release` + `renew` не помогают. Порт находится
  по MAC в таблице коммутатора; ловушка — сменить VLAN и не сохранить.
- **Пропавшая ретрансляция** (сеть) — после ночных работ у `Vlan20` на
  ядре нет `ip helper-address`. Причину первая линия находит, но чинить
  не вправе: образцовый исход — эскалация с доказательствами и
  предупреждённым заявителем.
- **Док-станция на гарантии** (оборудование) — Code 43 в диспетчере
  устройств; замена со склада, тикет ждёт поставку, старый док — вендору.
  Ловушка — утилизировать то, что вендор заменил бы бесплатно.
- **Изношенная гарнитура** (оборудование) — диспетчер видит её
  исправной, гарантия истекла: замена и утилизация. Ловушка — RMA:
  вендор отклонит, и неисправная вернётся на склад запасом.
- **DNS на списанном сервере** (сеть) — DNS вписан вручную на выведенный
  контроллер; `flushdns` и `release` + `renew` не помогают, источник
  виден в `netsh interface ip show dns`. Ловушка — публичный DNS:
  сайты откроются, внутренние имена нет (тихая поломка).
- **Статический адрес с чужим шлюзом** (сеть) — `renew` невозможен,
  `ping` наружу — «недостижимо» от себя, до шлюза сегмента — отвечает.
  Ловушка — поправить один шлюз: DHCP так и остаётся выключен.
- **Порт отключён защитой** (сеть) — мини-коммутатор в розетке, порт
  err-disabled; причина только в `show logging`, просьба убрать
  устройство открывается его прочтением. Поднять порт, не убрав
  устройство, — снова err-disabled; `switchport port-security` — отказ.

Команды: `npm run dev` (с API контента) · `npm test` · `npm run typecheck` · `npm run build` · `npm run build:server`

Ключ модели: скопировать `config/llm.local.example.json` в
`config/llm.local.json` (в `.gitignore`) и выбрать «Свой эндпоинт» в
настройках. Прокси dev-сервера подставит ключ заголовком; в бандл он не
попадает. Без файла прокси отвечает 503, и разговор идёт на репликах.

**Локальная модель — Qwen2.5 14B** (`ollama pull qwen2.5:14b`),
установлена и проверена вживую. Выбрана по русскому языку и
устойчивости в роли, а не по размеру: собеседник говорит одной-двумя
фразами и не должен съезжать в помощь техником. Mistral Nemo 12B
сравнивался тем же скриптом и проиграл: не срывался на китайский, зато
пересказывал системный промпт вслух.

Живая проверка промпта — `node scripts/probe-model.mjs [модель]`. Тесты
промпта работают на моках и доказывают лишь то, что разгадка не попала
в запрос; держится ли роль — видно только на настоящей модели. Скрипт
берёт промпт и параметры генерации из `prompt.ts` через esbuild:
собственная копия разошлась с кодом за один вечер.

**Ответ модели проверяется, а не принимается на веру** (`sanitize.ts`).
Qwen соскальзывает на китайский посреди русской фразы, Mistral цитирует
себя в кавычках и пересказывает инструкции. Негодная реплика — такой же
отказ, как обрыв связи: отвечают заготовки, техник видит плашку.
Размыкатель при этом различает «модель недоступна» (отключаем) и
«ответила негодно» (нет: следующий ответ может быть нормальным).

**«Попробуйте сейчас» отвечает мир, а не модель** — всегда, даже при
исправной модели. Найдено живой проверкой: блокировку сняли, флаг
`userConfirmed` встал, а модель по инерции твердила «всё ещё
заблокирована». Это реплика, которой закрывается цель и которую техник
цитирует в заметке; остальной разговор модель ведёт свободно.

**Правила интерфейса:** цвет означает суждение (приоритет, вердикт,
засчитано или нет) и больше нигде не появляется; скругление означает
интерактивность; шрифты только системные, потому что оффлайн.

**Формат вывода команд** сверен с живой Windows: метки полей `ipconfig /all`
лежат таблицей в `terminal/format.ts`, формулы для них не существует.
У `sc query` двоеточие на позиции 27, отступ восемь пробелов. У карточки
`net user` метка занимает 29 символов без двоеточия, значение начинается
с тридцатой позиции; у карточки группы — 15. Таблица `whoami /groups`
разложена по колонкам 68/16/108/50.

**Окно и команда — оба представления, операция одна.** Останов службы живёт
в `core/device/services.ts`, операции над учётками — в
`core/directory/accounts.ts`, и команда с кнопкой вызывают именно их. Тест
на побайтовую неотличимость этих путей обязателен.

**Состояние окон отдельно от `WorldState`**: свернув окно, техник не меняет
мир. Размер рабочего стола передаётся оконному менеджеру через `setViewport`.

**Визуальная проверка обязательна.** Четыре раза она находила то, чего тесты
не видели: оценку до закрытия тикета; окна, вылезающие за край области;
кнопку просьбы, печатавшую диагноз прямо в тикете; расследование мышью,
которое оценка не засчитывала вовсе. В срезе 6А — ещё три: таблицы IOS,
разваленные переносом строк; пустые строки вывода, схлопнутые в обоих
терминалах (у `ipconfig` — со второго среза); рейл, не отмечавший
сделанную передачу заявки. В срезе 6В — два источника статьи, читавшиеся
как дубль одной строки, и номер `KB-0001`, разорванный переносом. В
срезе 7А — верно отвеченная проверка, оставшаяся с активными вариантами,
и несданный квиз, говоривший «Неверно» без того, что было выбрано. В
срезе 7Б — полоса этапов интервью, слипшаяся в «Знакомство2. Рабочие
ситуации», и пункты разбора не в порядке вопроса. В срезе 8Б — четыре:
отменённый тикет ретрансляции, оставивший VLAN 20 без DHCP до конца
смены; трей «Подключено» при чужом шлюзе и мёртвом DNS; адрес в
карточке тикета у машины без линка; легенда портов без err-disabled.

**Порт коммутатора — источник линка и VLAN машины.** Адаптер знает только
свой конец кабеля (`linkUp`); есть ли у машины сеть и в каком она
сегменте, спрашивается у порта (`network/link.ts`). Хранить VLAN в двух
местах значило бы получить машину в одном сегменте, а порт в другом.
DHCP так же выводится, а не хранится: область жива, интерфейс VLAN
поднят, ретрансляция ведёт на сервер — три условия, каждое ломается
отдельно.

**Первая линия меняет только порт машины из тикета.** Шлюз смотрит на
`session.incident`: чужой порт, магистраль, интерфейс VLAN, сервер, всё
без тикета — отказ, записанный опасным действием. Консоль печатает его
как `Command authorization failed.`, кнопки серверной — словами; кнопки
при этом есть и нажимаются. Консоль без взятого тикета работает на
черновом журнале: после закрытия `session` ещё хранит прежний инцидент,
и его порт оставался бы «своим».

**Эскалация — честный исход со своей оценкой.** Вместо «заявитель
подтвердил» — «заявитель предупреждён о передаче» (`userInformed`),
вместо «внесённое изменение» — что передано и с какой проверкой за
пределами машины. Самоназначенный адрес — тихая поломка только при коде
«решено». Общую систему чинит её владелец (`onEscalate`) после оценки,
чтобы разбор видел мир таким, каким его оставил техник, и до наполнения
очереди, чтобы следующий тикет пришёл в починенный мир, — **при любом
коде закрытия**: отменённый тикет ретрансляции оставлял VLAN 20 без DHCP,
и каждый следующий сетевой тикет смены был непроходим (найдено в 8Б).
Скрытый тикет пока не чинит: его поломка ждёт возвращения в окно.

**DNS бывает вписан вручную при адресе по DHCP** (`Adapter.dnsSource`).
Аренда, `release` и самоназначение ручной DNS не трогают — поэтому
`renew` в сценарии со списанным DNS ничего не меняет. `ipconfig /all`
источник не показывает, `netsh interface ip show dns` — показывает:
в этом и диагностика. Операции над адаптером — `core/device/adapter.ts`;
`netsh` отдаёт в журнал полную форму (`CommandResult.canonical`), и цели
перечисляют её одну вместо записей ip/ipv4, `name=`, кавычек.

**Err-disabled снимает только `shutdown` + `no shutdown`.** Один
`no shutdown` на порту, отключённом защитой, ничего не меняет, как на
настоящем коммутаторе. Пока в розетке чужое устройство (`intruder`),
поднятый порт снова уходит в err-disabled с двумя записями журнала.
Защита порта — защитный контроль, как фаервол: правка — отказ шлюза.

**Интернет в трее — как у Windows** (`internetOf`): линк, шлюз сегмента
и отвечающий DNS. Чужой шлюз и мёртвый DNS — «Без доступа к интернету»,
публичный DNS вручную — «Подключено»: ловушка и должна выглядеть
починкой.

**Исправность периферии хранится в учёте.** Диспетчер устройств выводит
строки дока, гарнитуры и мониторов из активов, подключённых к машине
(`device/peripherals.ts`): замена в CMDB чинит машину без синхронизации
двух копий. Учёт меняют только операции логистики — ручная правка
учила бы «поправить запись вместо дела». Исправность — правда мира, а
не поле учёта: интерфейс её не показывает, иначе подсказка выдавала бы
находку.

**Время этапа — от оформления, а не от тика.** `advanceShipments`
ставит каждому этапу момент «оформление плюс длительности»: тик раз в
секунду и тик после десяти минут сна дают один мир. Эффект этапа
применяется ровно при переходе.

**Ждущий тикет паркуется.** «Ждём поставку» отпускает слот «одного в
работе», журнал, вывод, консоли и окна инцидента уходят в `parked` и
возвращаются при повторном взятии. Сброс смены и скрытие тикета
парковку забывают: номер тикета выводится из сценария, и вернувшийся
экземпляр нашёл бы чужой журнал.

**`exists` — единственный предикат, которому можно не найти.**
«Отправление вендору оформлено?», «исправный док подключён?» — «нет»
здесь законный ответ. Только для выбора по полю в конце пути над
существующим массивом; всё остальное на пустом пути падает громко.

**Общий ресурс — то же правило, что одна машина.** Сценарии с одним
`resources` (`dhcp:vlan20`) в окне смены не встречаются: сломанная
ретрансляция сделала бы непроходимым любой сетевой тикет этого VLAN.

**Одна статья на проблему.** Ключ статьи — сценарий: повторное закрытие
той же проблемы добавляет источник, а текст не трогает — иначе каждая
смена плодила бы дубли, а известная проблема одна. Черновик дают любые
закрытия с непустой заметкой, кроме «Отменено»: плохая заметка даёт
плохой черновик, и это урок. Статьи с нуля не пишутся — база
наполняется закрытыми тикетами, иначе она стала бы блокнотом.

**Источник статьи — прохождение, а не номер тикета.** Номер выводится
из сценария и у повторов одинаков; `sources` хранит id записи истории
(`смена:номер`). Поэтому и на экране источник — номер, дата и вердикт:
без них два прохождения читались как одна строка дважды.

**База — часть прогресса.** Статьи заработаны игроком и лежат в
`Progress.kb` рядом с историей, в IndexedDB. Прогресс прошлого формата
без `kb` читается целиком как «статей нет» (`normalizeProgress` в
`loadProgress`): сбрасывать историю из-за добавочного поля значило бы
потерять прогресс на ровном месте. Гидратация сливает базу через
`mergeKb`: загруженное первым, статья того же сценария из памяти
сливает источники, остальные получают следующие номера. Оценка от
базы не зависит: чтение своей статьи — законный приём, в журнал оно
попадает осмотром `kb:<номер>`, но баллов не даёт.

**Урок без проверки не пропускается.** Урок пройден, когда все его
проверки отвечены верно, — и урок без проверок проходился бы сам
(`[].every()` истинно), как цель без доказательств. Загрузчик курсов
падает на нём при запуске, с адресом `курс/секция/урок`, как на любом
варианте без разбора.

**Секции — по квизам, уроки — по порядку.** Следующая секция открывается
сданным квизом предыдущей (4 из 5), урок — пройденным предыдущим, квиз —
когда пройдены все уроки секции. Статусы выводятся из прогресса по
текущей редакции курса, а не хранятся: адрес проверки, которой больше
нет, не участвует, новая проверка честно переоткрывает урок. Правило
живёт в сторе: ответ в закрытом уроке — отказ, спрятанная кнопка
защищает только от мыши.

**Несданный квиз не выдаёт ответов.** Разбор объясняет только неверно
выбранное и называет, что выбрано; верные ответы показываются после
сдачи. Иначе пересдача превращается в переписывание с экрана.

**Практика — по правилам очереди.** Урок открывает свой тикет так же,
как очередь: свой в работе — открыть, чужой — отказ «сначала завершите
текущий тикет», в окне смены — взять. Тикета в окне нет — новая смена с
ним первым, но только с подтверждением: отложенные тикеты («Ждём
поставку») называются до него. Курс — не чёрный ход мимо правил первой
линии. Очков за обучение нет: оценка считает работу по тикету.

**Интервью ведёт движок, модель только оживляет.** Порядок вопросов,
уточнение (один раз, при доле пунктов меньше половины), переход между
этапами и вердикт считает `core/interview/`; вопрос всегда звучит
текстом контента — иначе разбору не с чем сверяться. Модель даёт лишь
реакцию на ответ (без оценки и подсказок) и ответы на вопросы
кандидата; без неё — нейтральная реплика по кругу и заготовки `faq`.
Оценка одна при любом режиме: пункт прозвучал, если в ответе есть его
маркер — основа слова до чередования («освобо») или команда. Маркер не
может повторять слово самого вопроса — иначе пункт засчитывался бы за
пересказ вопроса; это проверяет тест трека.

**Интервьюер не знает ответов.** В промпт уходят имя интервьюера,
факты о компании, текст вопроса и реплики — ни образцового ответа, ни
уточнения, ни пунктов. Тест по всей библиотеке треков считает открытым
лишь то, что и так звучит в комнате (шаблон, вопрос, имя, факты), и
однажды поймал подсказку внутри факта о компании («передача через
тикет с доказательствами» — ответ на вопрос об эскалации).

**Опыт — из вашей истории.** Вопрос об опыте задаётся про сценарий,
закрытый не провалом; нет таких — общий вопрос о трудном случае.
Технические вопросы идут по кругу от номера попытки: без случайности и
без повтора подряд. Незаконченное интервью не сохраняется, прервать его
можно только с подтверждением; интервью не трогает ни очередь, ни мир,
ни `session`.

**Какие тесты писать** (набор пересобран 27.09: 872 → 237 при том же
покрытии, пользователь: «тестов слишком много»). Тест называет поломку,
которую ловит, и проверяет настоящий код, а не заглушку.
- **Одно поведение — один тест.** Грани одного действия («проходит»,
  «помечено», «записано в журнал») — несколько `expect` в одном тесте, а
  не пять тестов. Варианты одного поведения — таблица литералов внутри
  теста с подписью: `expect(x, name)`; `it.each` не нужен.
- **Вывод команд — эталонным текстом целиком**, снятым с формата живой
  Windows (`toEqual({ exitCode, stdout })`), а не по кусочку на тест.
  Эталон ловит и то, что кусочки не проверяли.
- **Поведение проверяется на слое, которому принадлежит.** Операции — в
  `core`; стор — только свою логику (проводка, изоляция инцидентов,
  устаревший ответ); `src/e2e.test.ts` — образцовый проход каждого
  сценария и его развилки, по разделу на сценарий.
- **Ожидаемое значение — литерал**, выведенный руками, а не вызовом
  проверяемого кода. Проверки решений («константа равна 5», «команды
  строчными») не пишутся: они падают на редизайне и спят на дефектах.
- **Обязательные остаются всегда:** регрессия на каждый найденный дефект
  (с его историей в комментарии), «окно и команда неотличимы», утечка
  разгадки в модель — по всей библиотеке сценариев.
- **Проверка «не ослабили»** при чистке тестов: покрытие до и после плюс
  мутанты — старый набор их ловит, новый обязан тоже.

**Цель обязана быть недостижимой.** Доказательства три: запущенная команда,
флаг сессии, состояние мира — хотя бы одно. Цель без доказательств
засчитывается всегда (`[].every()` истинно), и разбор начинает врать;
загрузчик такую цель не пропускает. Внутри `commands` доказательства
соединены «или»: `net user x` и запись `gui:user:x` отвечают на один
вопрос, и требовать оба значит наказывать за выбор инструмента.

**Заявитель — не оракул.** Он сообщает то, что видит: и при звонке
(`confirmReplies`), и в ответ на просьбу (`replyIfBroken`). Статический
ответ дважды приводил к тому, что он подтверждал непочиненное.

**Просьба к заявителю открывается расследованием** (`unlockedBy`). Текст
просьбы — это диагноз, и кнопка, видимая с первой секунды, обесценивает
развилку сценария. Правило живёт в сторе, а не в интерфейсе: спрятанная
кнопка защищает только от мыши.

**Права выдаются при входе.** `hasShareAccess` смотрит на `tokenGroups` —
билет сеанса, — а не на членство в каталоге; `relogin` перевыпускает билет.
Отсюда `net user` показывает новую группу сразу, а `whoami /groups` — только
после повторного входа, и это расхождение есть штатный способ диагностики,
а не рассогласование источников.

**Инъекция копирует значение** (`structuredClone`): сценарий — модульная
константа, и присвоение по ссылке приводило к тому, что первая мутация
портила её на все последующие запуски.

**Нерабочий путь падает громко** — и в `setPath`, и в `checkHolds`.
Молчаливое «не выполнено» превращало опечатку автора сценария в
непроходимый сценарий без всякого следа.

**Модели уходит только `PersonaBrief`** — сводка, из которой вырезаны
корневая причина, цели, тексты просьб и ловушки. Проверяется тестом по
всей библиотеке сценариев, а не аккуратностью автора следующего.
Особенно тексты просьб: «учётку блокирует почта на телефоне» — это
разгадка словами заявителя, и странно прятать кнопку, чтобы тут же
отдать тот же текст модели.

**Отказ модели обязан деградировать на реплики** — с плашкой, без
падения. После первого отказа размыкатель отключает модель до смены
настроек: иначе каждая реплика ждёт таймаут, а консоль копит отказы
соединения, которых мы не контролируем.

**Асинхронный ответ проверяется на устаревание.** Пока модель думает,
техник может закрыть тикет или начать заново. Ответ в изменившийся мир
отбрасывается: иначе реплика дописывается в закрытую переписку, а
`userConfirmed` поднимается после того, как разбор посчитан.

**Надбавка не дотягивает до максимума.** Масштаб и связь добавляют
балл, но десятка — только за полную базу. Простой потолок давал 10 при
«закрыто 1 из 2»: измерение противоречило собственному объяснению.

**Сохраняется прогресс, а не мир.** История прохождений, очки, ранг и
профиль переживают перезагрузку; `WorldState` собирается из seed
заново. Отсюда два следствия, оба намеренные: перезагрузка начинает
новую смену, незакрытый тикет не восстанавливается.

**Счётчики выводятся из истории, а не инкрементируются.** Счётчик,
который увеличивают при закрытии, расходится с историей при первом же
сбое записи — и дальше разбор показывает одно, а список другое.
Пересчёт по записям стоит долей миллисекунды и врать не умеет. То же
правило поймало «Завершённых: 0» в очереди: окно смены убирает
закрытый тикет, и вычитание из очереди всегда давало ноль.

**Состояние правится синхронно, хранилище получает его следом.** Пока
идёт `await` записи в IndexedDB, стор обязан уже отвечать новым
значением: иначе второе закрытие читает старое и затирает первое. И
гидратация дописывает загруженное перед накопленным, а не заменяет
его — иначе отказ хранилища в приватном окне стирает уже закрытое
прохождение.

**Интерфейс не вызывает `start()`.** Стор собирает смену сам, в
инициализаторе. Всё, что нужно сделать один раз при запуске, вешается
на создание стора, а не на `start` — его зовут только тесты, и
дефект, повешенный на него, зелёными тестами не ловится.

**«Тикетов нет» и «тикетов больше не будет» — разные состояния.**
Второе обязано быть названо словами: молчаливо опустевшая очередь
читается как поломка тренажёра, а не как конец смены.

**Подтверждение необратимого не встаёт под курсор.** Кнопка
подтверждения появляется на месте нажатой — React переиспользует узел,
— и получает фокус. Безопасное действие идёт первым, иначе двойной
клик по инерции срабатывает раньше, чем человек прочитает вопрос.

**Журнал сессии принадлежит инциденту, а не смене.** `session` есть
вход для всей оценки, и при переходе к другому тикету он начинается
заново — вместе с разговором, окнами и выводом терминала: собеседник
другой, машина другая. Мир при этом общий намеренно: последствия
работы переживают инцидент, иначе тихие поломки перестали бы быть
тихими. Возврат к своему же тикету новым инцидентом не считается и не
стирает ничего.

**Повторяемое действие остаётся доступным.** Просьба «выйдите и
войдите заново» — обычное действие первой линии, и попросить о ней до
того, как найдена причина, естественно: заявитель честно выполнит и
скажет, что не помогло. Кнопка, выключенная после первой просьбы,
закрывала единственный путь к решению навсегда и делала сценарий
непроходимым.

**Прочитанное из хранилища — `unknown`, пока не проверено.** Типы
TypeScript до границы IndexedDB не достают: данные мог записать
прошлый формат, повредить прерванное обновление, подменить кто угодно
из консоли. Проверка обязана пережить любую форму и не бросать:
исключение внутри колбэка запроса не ловится окружающим `try/catch`,
промис остаётся неразрешённым, и загрузка висит вечно.

**Про «защиту от консоли браузера».** Всё, что отдано браузеру —
код, данные, сценарии, — принадлежит тому, кто этим браузером
управляет. Минификация, отсутствие глобальных экспортов и блокировка
горячих клавиш инструментов разработчика границей полномочий не
являются и создают лишь видимость защиты. Единственная настоящая
граница — сервер: секреты и закрытое содержимое живут там, и каждая
операция проверяется на нём заново. Пока тренажёр целиком клиентский,
любой его локальный счёт правится из консоли, и это цена оффлайна,
принятая осознанно. Ключ модели уже за этой границей: он лежит вне
репозитория, подставляется прокси dev-сервера и в бандл не попадает.

**Граница контента — сервер** (срез 8А). Браузер получает только то,
что нужно для хода игры, и только когда ход наступил: каталог (карточки
тикетов, оглавления курсов, треки) — сразу; капсулу тикета (поломка,
персона, реплики подтверждения, id просьб) — при входе тикета в окно
смены; текст урока и вопросы квиза — при открытии; верен ли ответ, ушла
ли проблема, текст и эффект просьбы, оценка с причиной, уточнение и
пункты интервью — ответом сервера. Причина хранится в карточке разбора,
пункты — в результате интервью, верный ответ проверки — в прогрессе:
у браузера нет библиотеки, откуда их взять. `src/bundle.test.ts`
собирает `src/main.tsx` и проверяет и входы, и текст по всей библиотеке;
`service.test.ts` — то же для ответов сервера до срока. Секрет — строка
решения, которой нет в открытом материале: курс законно учит тому же,
что требуют цели.

**Сервер без своего состояния.** Мир, журнал, запуск интервью присылает
клиент; подделка своего мира обманывает только игрока. Капсула несёт
подпись `<сценарий>.<выдано>.<HMAC>` на сутки: без неё проверка, просьбы
и оценка — 403, иначе разбор любого сценария вынимался бы одним
запросом. Лимиты на IP — против скрипта, а не против F5: при 12
капсулах и одной в минуту четыре перезагрузки подряд запирали тренажёр
(найдено в браузере), сейчас 30 / одна в 20 секунд.

**Синхронный разъём не добавляет ни такта.** Ответ — значение или
промис (`MaybePromise`); сервис отвечает значением, и все прежние тесты
идут на нём, не замечая сети. Ждать — только настоящий промис
(`isThenable(x) ? await x : x`): лишний `await` сдвигал запрос к модели,
и тесты «ответ, пришедший позже» висели. Асинхронный путь проверяется
`deferred`-разъёмом: загрузка смены, сбой с «Повторить», ответ для
прежней смены отбрасывается, оценка правит запись, мир и очередь только
после ответа, сбой оставляет тикет открытым.

**Тексты просьб принадлежат инциденту.** Хранились по сценарию — и
тикет, скрытый и взятый снова (новый инцидент, флаги сброшены),
показывал бы диагноз на кнопке до расследования. Найдено при переносе;
регрессия в `ask.test.ts`.

**Что от копирования защищает на самом деле** (1.10, по просьбе «чтобы
нельзя было украсть с сайта»). Главное — сервер контента выше; здесь —
то, что работает и без него. Запрет встраивания — `frame-ancestors
'none'` и `X-Frame-Options` (`public/_headers` для Cloudflare,
`deploy/nginx.conf` для Pi — nginx `_headers` не читает): чужой сайт не покажет
тренажёр у себя во фрейме, и проверяет это браузер посетителя, а не наш
код (Chromium: без заголовка встраивается, с ним — `Refused to frame`).
Pages и статика Worker читают файл одинаково, наружу он не отдаётся.
Права заявлены в `LICENSE`, `package.json` (`UNLICENSED`) и уведомлением
в начале бандла; оно ставится после минификации (`banner` Rollup
минификатор вырезает) и входит в хеш имени — ассеты кэшируются на
четыре часа, и файл с уведомлением под прежним именем остался бы без
него. Бандлу — `noindex`: сниппет из него в выдаче показывал бы ответы.
Запрет обучения в robots.txt ведёт Cloudflare на уровне зоны.
Обфускация, «защита» от devtools, привязка к домену и шифрование
сценариев ключом из того же бандла не делаются: снимаются за минуты, а
платит за них игрок размером и скоростью. То, что простые сборщики без
JS видят только заголовок, — тоже не защита: бандл лежит обычным
текстом по ссылке из `<script src>`. Исходники в публичном репозитории —
утечка больше бандла; пользователь закроет его сам.

## Ключевые архитектурные решения

- **Подход A: единое состояние мира.** `WorldState` — единственный источник истины,
  все инструменты (терминал, GUI-окна, AD-консоль, телефон) — окна над ним.
  Собственного состояния не хранит никто. Отсюда бесплатно берётся связность,
  за которую ориентир берёт деньги.
- **Сценарий = инъекция поломки, не скрипт.** Файл описывает, во что сломан мир и
  что считается решённым. Не описывает шаги. Цена нового сценария ≈ 30 строк JSON.
- **Команда = чистая функция** `run(cmdline, world, session) → {stdout, exitCode, mutations}`.
  Вывод рендерится из состояния, форматом побайтово похож на настоящий Windows.
- **Один шлюз полномочий** `authorize(действие, world, session)`. Шесть правил
  (личность до изменения аккаунта, не отключать защиту, не менять общее ради одного,
  предупреждать перед действием, эскалировать вне прав, фиксировать отказ).
  Действует одинаково для всех инструментов.
- **Граница обозначается, а не прячется** — и разница в природе запрета:
  `deny` — действие физически невозможно (отключить защиту, выдать или
  отобрать права администратора домена); `flag` — возможно и является
  ошибкой суждения (сброс пароля без сверки личности) — проходит,
  помечается несанкционированным, стоит балла и всплывает в разборе.
  Спрятанная кнопка учила бы, что границ нет, их просто не показывают.
  Границы двусторонние: если нельзя добавить в привилегированную группу,
  то нельзя и исключить.
- **Сверка личности относится к конкретной учётке** (`session.verifiedAccount`),
  и это настоящая проверка, а не кнопка «я подтвердил»: техник выбирает
  контрольное поле, вводит услышанный ответ, ответ сверяется с каталогом.
  Сверив одного обратившегося, техник не получает права менять чужие аккаунты.
- **Часть работы делает заявитель** (`asks` в сценарии): убрать старый пароль
  с телефона, выйти и войти заново. Без этого целый класс правильных решений
  невыразим — тот самый, который отличает «снял симптом» от «устранил причину».
- **`session` — журнал действий игрока, и это вход для всей оценки.**
- **Оценка work note без модели — сверкой с журналом.** Мы знаем, что реально
  произошло, поэтому проверяем, названы ли реальные команды, реальные значения,
  реальное подтверждение юзера. Не ключевые слова.
- **Разъём диалога** с тремя взаимозаменяемыми реализациями (скрипт / Ollama / API)
  и обязательной деградацией на скрипт при недоступности модели.
  **Модели никогда не передаётся корневая причина** — иначе она выдаст диагноз.

## Порядок сборки

Срезами, каждый заканчивается играбельным состоянием. Сделано: 0–7 (6А, 6Б, 6В, 7А, 7Б), 8А (сервер контента) и 8Б (сетевой пакет).

0. Скелет (мир, оболочка, очередь, тикет) → 1. Терминал (**первый настоящий
тикет — APIPA**) → 2. Удалёнка (рабочий стол, окна, журнал событий, службы)
→ 3. Каталог (учётки, группы, сверка личности, консоль) → 4. Люди
(телефон/почта/чат + разъём диалога) → 5. Прогрессия (память: очки, ранги,
история, профиль) → **6. Инфраструктура** (серверная, CLI коммутатора,
CMDB, логистика, база знаний) → 7. Курсы и интервью → 8. Контент (месяцы)

Нумерация — по спеке и дорожной карте. Раньше здесь стояло «6. Стенды и
интервью → 7. Контент»: срезы 6 и 7 были слиты в один, и план среза 6
было не из чего писать.

База знаний из среза 4 переехала в срез 6 (задачи 6.7–6.8) — она
наполняется закрытыми тикетами, и история прохождений для неё нужна
была раньше. Сделана подсрезом 6В.

Порядок 2 и 3 поменялся местами против первоначального плана: удалёнка
понадобилась раньше каталога, потому что первые два сценария живут на
машине.

## Что уже выяснено про ориентир

Разведка сделана дважды: по публичным страницам и **изнутри продукта с логином**
(Chrome + devtools). Всё вшито в спеку. Главное:

- **Шесть измерений оценки:** владение тикетом, расследование, документация,
  коммуникация, границы полномочий, качество решения.
- **Проверено живьём:** формат вывода команд настоящий; состояние мира реально
  меняется (`/release` + `/renew` → APIPA стал валидным адресом, трей сам
  переключился на «connected»); порядок команд важен (`renew` в одиночку падает);
  `netsh advfirewall ... state off` → **`Access is denied.`**
- **Оценка настоящая.** Задача решена верно и заметка подробная — вердикт всё
  равно **PARTIAL «process/comms can improve»**, потому что не перезвонил юзеру
  после починки. Доктрина «подтверждает заявитель, а не техник» реально считается.
- **Заявитель — не оракул.** В логе звонка он спорил «у меня всё ещё ошибка»,
  хотя машина уже была починена.
- **Кнопка Solution выдаёт схему сценария:** rootCause + список целей
  (заголовок, шаги, команды, «зачем») + actionsToAvoid. Процессные цели
  (подтвердить у юзера, написать заметку, выбрать код) — наравне с техническими.
- **Один тикет в работе за раз.** Удалёнка только к машине с открытым тикетом.
  Изменения инфраструктуры и отправка оборудования — только по тикету.
- **База знаний пустая на старте** и наполняется вашими закрытыми тикетами.
- **Удалёнка — целый рабочий стол Windows**, а не набор окон с инструментами.
- **Тихие поломки** — отдельная метрика: сломал и не знаешь.
- **Пародийные бренды** системно: MicroCore Windows, Aster Browser, NorthMail,
  Lenova, Deltatek, HelixPrint, Orchard, Ciscora, TeamLine, NorthDrive. Нам нужен
  свой такой словарь.
- **Звонок** — полный контур микрофон → распознавание → LLM → синтез речи.
  Бесплатный локальный аналог: whisper.cpp + Ollama + Piper.
- **Цены:** Free — 5 тикетов и 1 звонок в сутки, AD и интервью закрыты;
  $7.99 — расширенные лимиты; $14.99 — безлимит.
- Категории сценариев: identity · networking · Windows desktop · software ·
  hardware · printers · mobile · security · infrastructure.

**Не выяснено:** голосовой звонок вживую (браузер под автоматизацией блокирует
аудио); объекты AD и интервью закрыты бесплатным планом.

## Как работать

### Сначала скилл, потом дело

Перед любым действием — прочитать код, ответить, спланировать, править,
отлаживать — загрузить подходящий скилл инструментом Skill и дальше следовать
ему. Если есть хоть малый шанс, что скилл подходит, — загрузить. Слова
пользователя: «скиллы, MCP и плагины использовать — это важно».

| Что делаю | Скилл |
|---|---|
| новая возможность или переделка (срез) | `superpowers:brainstorming` → `superpowers:writing-plans` → `superpowers:executing-plans` |
| любой код с поведением | `superpowers:test-driven-development` |
| провал проверки, странное поведение, ошибка | `superpowers:systematic-debugging` |
| перед словами «готово», «работает», «проходит» | `superpowers:verification-before-completion` |
| конец ветки | `superpowers:finishing-a-development-branch` |
| разбор кода перед правкой | `codebase-memory` (граф codebase-memory-mcp) |
| интерфейс, новые экраны инструментов | `frontend-design:frontend-design` — в пределах правил интерфейса выше |
| дать работу агентам | `superpowers:dispatching-parallel-agents` |
| проверить свою работу | `superpowers:requesting-code-review` или `code-review` |
| увидеть изменение в браузере | `run` — визуальная проверка обязательна, см. выше |

Скиллы исполнять в этом же сеансе.

### Граф кода — всегда

Код искать и разбирать через граф codebase-memory-mcp, а не только grep и
чтением файлов: `search_graph` — найти символ, `trace_path` — кто вызывает и
что вызывает, `get_code_snippet` — исходник, `detect_changes` — что задевает
правка, `check_index_coverage` — для каждого файла, на который опираюсь. Перед
любой правкой посмотреть по графу вызывающих и вызываемых. grep — для текста, а
не для структуры кода. Имя проекта в графе выводится из пути — `list_projects`
покажет.

### Агенты

Пару агентов можно запускать и без отдельной просьбы. **Модель агентов —
всегда Haiku**: `model: "haiku"` в Agent; без этого агент наследует основную
модель. Агенту — то, что отделимо и не требует всей картины: поиск в сети,
разбор кода по узкому вопросу, отдельный файл по чёткому интерфейсу. Задание
узкое, с явным списком файлов или вопросов, ответ короткий. Результат агента
проверять самому.

Задание начинается строкой о том, какие скиллы агент загружает до любого
действия (разбор кода — `codebase-memory`, ошибка —
`superpowers:systematic-debugging`, проверки —
`superpowers:test-driven-development`), затем «Только чтение, ничего не правь
и не запускай. Экономь токены: читай только перечисленное.», затем точный
список файлов, что искать, что не считается находкой, что уже известно. Ответ
не длиннее 10 строк `файл:строка — выражение — почему`; поиск в сети — не
длиннее 14 строк `факт — ссылка`.

| Задача агенту | `subagent_type` | Что ещё |
|---|---|---|
| найти место в коде, узкий вопрос | `codebase-memory-scout` (локально), `Explore` (в облаке) | только чтение |
| разобрать ограниченную область целиком | `codebase-memory-auditor` (локально), `Explore` (в облаке) | только чтение |
| исправить код, написать проверку | `general-purpose` | `isolation: "worktree"`; разницу сверяю и переношу сам |
| поиск в сети | `general-purpose` | ответ ≤ 14 строк `факт — ссылка` |

### Облачная сессия

Облачный контейнер — не машина пользователя: плагины, MCP-серверы и агенты
`codebase-memory-*` там стоят не сами по себе.

- **Плагины в облачных сессиях недоступны** — только в локальных. Поэтому
  скиллы Superpowers и frontend-design лежат копиями в `.claude/skills/`
  репозитория и подхватываются в любой сессии. Имена там без префикса:
  `superpowers:brainstorming` из таблицы выше в облаке — это `brainstorming`.
  Источник, версии и лицензии — `.claude/skills/README.md`.
- **Граф кода** — локальная программа, а не коннектор claude.ai. Готовые сборки
  с GitHub прокси не отдаёт, пускает только `git clone`, поэтому граф собирается
  из исходников (~5 минут, бинарник ~300 МБ). В облаке он работает через Bash в
  режиме `cli`, без подключения MCP; аргументы — JSON на стандартный вход:

  ```bash
  echo '{"repo_path":"/home/user/website"}' | codebase-memory-mcp cli index_repository
  echo '{"project":"home-user-website","name_pattern":"^fillQueue$"}' | codebase-memory-mcp cli search_graph
  echo '{"project":"home-user-website","function_name":"fillQueue","direction":"inbound","depth":2}' | codebase-memory-mcp cli trace_path
  ```

  Проект в облаке называется `home-user-website`. Контейнер одноразовый, и
  чтобы граф был в каждой сессии, сборка должна стоять в setup script
  окружения (меню облачного окружения в заголовке сессии → Edit → Setup
  script):

  ```bash
  if ! command -v codebase-memory-mcp >/dev/null; then
    git init -q /opt/cbm-src && cd /opt/cbm-src
    git fetch -q --depth 1 https://github.com/DeusData/codebase-memory-mcp 5df8b0442c48fed654c6f11d94cb6f64f00fc368
    GIT_LFS_SKIP_SMUDGE=1 git checkout -q FETCH_HEAD
    make -f Makefile.cbm -j"$(nproc)" cbm
    install -m755 build/c/codebase-memory-mcp /usr/local/bin/codebase-memory-mcp
    cd / && rm -rf /opt/cbm-src
  fi
  ```

  Сборка стороннего кода в автоматическом режиме блокируется фильтром
  безопасности — внутри сессии её подтверждает пользователь, setup script
  этого не требует.
